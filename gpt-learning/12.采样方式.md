这段代码的核心逻辑可以概括为：

> **Prefill：一次性读完 prompt，把所有历史 token 的 K/V 存起来。**
> **Decode：之后每次只输入最新生成的 1 个 token，利用缓存预测下一个 token。**

`GPT2WithKVCache` 本身只是一个薄包装，真正的注意力计算应当在没有展示出来的 `gpt2.forward_with_kv()` 中。`batched_generate()` 负责组织 prefill、decode 和采样流程。

---

# 一、没有 KV Cache 时，生成为什么很浪费

假设 prompt 是：

```text
我 喜欢 学习
```

准备生成三个 token。

普通生成可能这样做：

```text
第 1 次：输入 [我, 喜欢, 学习]               → 预测 Python
第 2 次：输入 [我, 喜欢, 学习, Python]       → 预测 和
第 3 次：输入 [我, 喜欢, 学习, Python, 和]   → 预测 AI
```

每一步都重新计算：

```text
我、喜欢、学习
```

这些旧 token 的：

```text
Q、K、V
Attention
MLP
```

但它们其实早就算过了。

KV Cache 的思路是：

* 历史 token 的 `K` 和 `V` 保存下来；
* 后面只计算新 token 的 `Q、K、V`；
* 新 token 的 `Q` 与所有历史 `K` 做注意力。

---

# 二、Prefill 是什么

## 1. Prefill 的输入

代码中：

```python
logits, cache = wrapped_model(padded, cache, position_ids)
```

这里一次性把整个 prompt 放入模型。

假设：

```text
prompt = [A, B, C]
```

则：

```python
padded.shape       = (B, 3)
position_ids       = [0, 1, 2]
```

模型一次处理三个 token。

在每一层 Attention 中，大致执行：

```python
Q, K_new, V_new = calculate_qkv(x)

cache.append(layer_idx, K_new, V_new)

K_all, V_all = cache.get(layer_idx)

attention = softmax(Q @ K_all.transpose(-2, -1))
output = attention @ V_all
```

Prefill 结束后，每层缓存里都有：

```text
K_cache = [K_A, K_B, K_C]
V_cache = [V_A, V_B, V_C]
```

形状是：

```text
(B, n_head, prompt_len, head_dim)
```

例如：

```text
(B, H, 3, D)
```

---

## 2. Prefill 返回的 logits

Prefill 返回：

```python
logits.shape == (B, prompt_len, vocab_size)
```

也就是每个 prompt 位置都有一份预测结果：

```text
输入 A       产生 logits_A，预测 B
输入 A B     产生 logits_B，预测 C
输入 A B C   产生 logits_C，预测下一个 token
```

生成时只关心最后一个位置：

```python
next_logits = logits[:, -1, :]
```

假设最后预测出来：

```text
D
```

那么：

```python
next_tokens = D
```

注意：**第一个生成 token 是在 Prefill 结束后直接采样出来的。**

这时缓存里还只有：

```text
[A, B, C]
```

`D` 还没有进入缓存。

---

# 三、Decode 是什么

接下来进入循环：

```python
for step in range(max_new_tokens - 1):
```

为什么是 `max_new_tokens - 1`？

因为第一个 token 已经在 prefill 后采样出来了。

假设：

```text
prompt = [A, B, C]
第一个生成 token = D
```

第一次 decode 时输入：

```python
cur_token = D
```

位置是：

```python
position = 3
```

代码对应：

```python
pos = max_prompt_len + step
```

当 `step=0`：

```text
pos = 3
```

模型只计算新 token `D`：

```text
Q_D、K_D、V_D
```

然后把 `K_D、V_D` 添加到缓存：

```text
K_cache = [K_A, K_B, K_C, K_D]
V_cache = [V_A, V_B, V_C, V_D]
```

此时用：

```text
Q_D
```

关注：

```text
K_A, K_B, K_C, K_D
```

得到的 logits 用来预测下一个 token，例如：

```text
E
```

下一次 decode 输入 `E`：

```text
cache = [A, B, C, D, E]
```

再预测 `F`。

完整过程：

```text
Prefill:
输入 [A, B, C]
缓存 [A, B, C]
采样得到 D

Decode 第 1 步:
输入 [D]
缓存 [A, B, C, D]
采样得到 E

Decode 第 2 步:
输入 [E]
缓存 [A, B, C, D, E]
采样得到 F

最终结果:
[A, B, C, D, E, F]
```

---

# 四、Decode 中 Attention 的形状

假设：

```text
batch_size = 1
n_head = 4
head_dim = 32
prompt_len = 3
```

## Prefill

输入三个 token：

```text
Q_new: (1, 4, 3, 32)
K_new: (1, 4, 3, 32)
V_new: (1, 4, 3, 32)
```

Attention 分数：

```text
Q @ Kᵀ
(1, 4, 3, 32) @ (1, 4, 32, 3)
→ (1, 4, 3, 3)
```

每个 token 分别看前面的 token。

## 第一次 Decode

只输入新 token `D`：

```text
Q_D: (1, 4, 1, 32)
K_D: (1, 4, 1, 32)
V_D: (1, 4, 1, 32)
```

添加缓存后：

```text
K_all: (1, 4, 4, 32)
V_all: (1, 4, 4, 32)
```

Attention 分数：

```text
Q_D @ K_allᵀ
(1, 4, 1, 32) @ (1, 4, 32, 4)
→ (1, 4, 1, 4)
```

意思是：

```text
D 对 A、B、C、D 各有一个注意力分数
```

下一次 decode 时：

```text
Q_E:    (1, 4, 1, 32)
K_all:  (1, 4, 5, 32)
score:  (1, 4, 1, 5)
```

所以 decode 并不是“不看历史”，而是：

> **历史 token 的 K/V 不重新计算，但新 token 仍然会关注全部历史 K/V。**

---

# 五、为什么每层都有独立的 `_seq_lens`

缓存定义：

```python
self._seq_lens = [0] * n_layer
```

假设有三层 Transformer。

一次 prefill 处理三个 token：

```text
第 0 层 append 3 个 token：seq_len[0] = 3
第 1 层 append 3 个 token：seq_len[1] = 3
第 2 层 append 3 个 token：seq_len[2] = 3
```

如果只使用一个全局计数器：

```text
第 0 层 append 后：global_seq_len = 3
第 1 层会误以为要从位置 3 开始写
第 2 层又会从位置 6 开始写
```

这显然错误。

所以每一层必须分别记录写到了哪里。

# 六、一个容易混淆的地方：输入 token 与预测 token

假设 prompt 长度是 3：

```text
位置 0: A
位置 1: B
位置 2: C
```

Prefill 返回的位置 2 的 logits：

```text
logits at C → 预测位置 3 的 D
```

然后 decode 输入：

```text
位置 3: D
```

这次 forward 返回的 logits：

```text
logits at D → 预测位置 4 的 E
```

所以 decode 的逻辑不是：

```text
输入 D，预测 D
```

而是：

```text
输入刚刚生成的 D，预测下一个 E
```

# 七、采样到底有几种方式

这段函数是：

```python
_sample_from_logits(
    logits,
    temperature,
    top_k,
    top_p,
)
```

严格来说，这里面不是三个完全独立的采样器，而是：

1. greedy，直接取最大值；
2. temperature，调整概率分布；
3. top-k，筛掉排名靠后的 token；
4. top-p，筛掉累计概率之外的 token；
5. `torch.multinomial`，在剩余 token 中随机抽取。

其中 `temperature、top-k、top-p` 可以组合使用。

---

# 八、Greedy：贪心解码

代码：

```python
if temperature <= 0.0:
    return logits.argmax(dim=-1, keepdim=True)
```

假设词表只有四个 token：


| token | logits |
| ----- | -----: |
| A     |    5.0 |
| B     |    4.0 |
| C     |    2.0 |
| D     |    1.0 |

Greedy 永远选择 logits 最大的：

```text
选择 A
```

特点：

* 没有随机性；
* 相同输入永远得到相同输出；
* 通常比较稳定；
* 可能重复、呆板；
* 它没有执行后面的 top-k、top-p。

调用方式：

```python
temperature=0
```

---

# 九、Temperature：温度

代码：

```python
logits = logits / temperature
```

温度不是直接“删除 token”，而是改变概率分布的尖锐程度。

## `temperature = 1`

不改变：

```python
logits / 1 = logits
```

## `temperature < 1`

例如：

```python
temperature = 0.5
```

相当于：

```python
logits / 0.5 = logits * 2
```

大的 logits 变得更加突出，概率分布更尖锐：

```text
高概率 token 更容易被选中
低概率 token 更难被选中
```

表现：

* 更保守；
* 更稳定；
* 随机性较低。

## `temperature > 1`

例如：

```python
temperature = 2
```

所有 logits 差距缩小，概率更平均：

```text
低概率 token 也更容易被抽到
```

表现：

* 更随机；
* 更多样；
* 也更容易胡言乱语。

可以这样理解：

```text
temperature → 0：越来越接近 greedy
temperature = 1：原始分布
temperature > 1：越来越随机
```

不过这份代码规定：

```text
temperature <= 0
```

就直接走 greedy，不会真的执行除零。

---

# 十、Top-k：只保留概率最高的 k 个

代码核心：

```python
kth = logits.topk(top_k, dim=-1).values[:, -1:]
logits = torch.where(
    logits < kth,
    -inf,
    logits,
)
```

假设排序后的概率是：


| token | 概率 |
| ----- | ---: |
| A     | 0.50 |
| B     | 0.25 |
| C     | 0.15 |
| D     | 0.07 |
| E     | 0.03 |

设置：

```python
top_k = 2
```

只保留：

```text
A、B
```

其余 logits 设为：

```text
-inf
```

经过 softmax 后，它们的概率就是 0。

剩余 A、B 会重新归一化：

```text
A: 0.50 / 0.75 ≈ 0.667
B: 0.25 / 0.75 ≈ 0.333
```

然后随机抽一个。

特点：

* 候选数量固定；
* `top_k=1` 接近 greedy；
* `top_k=50` 表示只从概率最高的 50 个 token 中抽样。

---

# 十一、Top-p：保留累计概率达到 p 的最小集合

Top-p 也称为：

```text
nucleus sampling
核采样
```

仍然假设概率：


| token | 概率 | 累计概率 |
| ----- | ---: | -------: |
| A     | 0.50 |     0.50 |
| B     | 0.25 |     0.75 |
| C     | 0.15 |     0.90 |
| D     | 0.07 |     0.97 |
| E     | 0.03 |     1.00 |

设置：

```python
top_p = 0.8
```

依次累加：

```text
A           → 0.50，不够
A + B       → 0.75，不够
A + B + C   → 0.90，达到 0.8
```

因此保留：

```text
A、B、C
```

删除：

```text
D、E
```

Top-p 的候选数量不固定：

* 模型非常确定时，可能只保留 1～2 个；
* 模型不确定时，可能保留几十个甚至更多。

这是它和 top-k 最大的区别：

```text
top-k：固定保留 k 个
top-p：固定保留一定概率质量，token 数动态变化
```

---

# 十二、Top-p 代码中的 mask 为什么这样写

代码：

```python
cumsum = sorted_probs.cumsum(dim=-1)
mask = cumsum - sorted_probs > top_p
```

这里：

```python
cumsum - sorted_probs
```

表示“加入当前 token 之前的累计概率”。

这样可以保证：

> 让累计概率第一次超过 `top_p` 的那个 token 仍然被保留。

仍以 `top_p=0.8` 为例：


| token | 当前概率 | 加入前累计概率 | 是否删除 |
| ----- | -------: | -------------: | -------- |
| A     |     0.50 |           0.00 | 否       |
| B     |     0.25 |           0.50 | 否       |
| C     |     0.15 |           0.75 | 否       |
| D     |     0.07 |           0.90 | 是       |
| E     |     0.03 |           0.97 | 是       |

因此 C 虽然让累计概率从 `0.75` 变成 `0.90`，但它仍会被保留。

---

# 十三、最终真正执行随机抽样的是 multinomial

经过 temperature、top-k、top-p 后：

```python
probs = logits.softmax(dim=-1)
return torch.multinomial(probs, num_samples=1)
```

假设最后剩余：

```text
A: 0.65
B: 0.25
C: 0.10
```

`torch.multinomial` 类似抽奖：

```text
A 有 65% 概率被抽到
B 有 25% 概率被抽到
C 有 10% 概率被抽到
```

它并不是选择概率最大者。

所以即使 A 概率最高，也可能抽到 B 或 C。

返回形状：

```text
(B, 1)
```

即 batch 中每个样本分别抽一个 token。

# 十四、几种常见配置


| 配置                                      | 实际行为                                 |
| ----------------------------------------- | ---------------------------------------- |
| `temperature=0`                           | Greedy，永远取最大 logits                |
| `temperature=1, top_k=None, top_p=None`   | 从完整词表随机采样                       |
| `temperature=0.8, top_k=None, top_p=None` | 降温后，从完整词表采样                   |
| `temperature=1, top_k=50`                 | 只从概率最高的 50 个中采样               |
| `temperature=1, top_p=0.9`                | 从累计概率达到 90% 的候选中采样          |
| `temperature=0.8, top_k=50, top_p=0.9`    | 先降温，再 top-k，再 top-p，最后随机采样 |

这份代码的执行顺序是：

```text
1. temperature
2. top-k
3. top-p
4. softmax
5. multinomial
```

如果同时设置 top-k 和 top-p，最终候选是两次筛选之后的结果。

# 十五、这份代码中几个值得注意的问题

## 1. Left padding 没有看到 attention mask

代码将不同长度 prompt 左侧补 pad：

```text
短 prompt: [PAD, PAD, A, B, C]
长 prompt: [D, E, F, G, H]
```

但是当前包装接口只有：

```python
idx
cache
position_ids
```

没有看到：

```python
attention_mask
```

如果 `forward_with_kv()` 内部也没有根据 `pad_id` 屏蔽 PAD，那么短 prompt 的真实 token 会注意到前面的 PAD：

```text
C 会关注 PAD、PAD、A、B、C
```

这会影响结果。

同时，它给所有 batch 使用：

```python
position_ids = [0, 1, 2, 3, 4]
```

于是短 prompt 的 A、B、C 被放在位置 2、3、4，而不是 0、1、2。

因此，**除非 `forward_with_kv()` 内部另有 padding mask 处理，否则这个 batched left-padding 实现并不完整。**

---

## 2. finished 样本没有真的“冻结输出”

代码先把已经结束的样本输入改成 PAD：

```python
cur_token[finished] = pad_id
```

但是随后依然对整个 batch 采样：

```python
next_tokens = _sample_from_logits(...)
generated.append(next_tokens)
```

所以已经生成 EOS 的样本，EOS 后面仍可能出现随机 token。

更严谨的处理应保存旧状态，例如：

```python
was_finished = finished.clone()

next_tokens = _sample_from_logits(...)

next_tokens[was_finished] = pad_id

finished = was_finished | (next_tokens.squeeze(-1) == eos_id)
```

这样 EOS 之后才会稳定补 PAD。

---

## 3. KV Cache 的 device 和 dtype 可能不匹配

`KVCache` 中创建缓存时：

```python
torch.zeros(...)
```

没有传：

```python
device=model_device
dtype=model_dtype
```

因此默认通常是：

```text
CPU + float32
```

如果模型在：

```text
CUDA + float16
```

那么缓存会不匹配，可能直接报错或产生额外转换。

更合理的构造方式是给 `KVCache` 增加：

```python
device: torch.device
```

并创建为：

```python
torch.zeros(
    ...,
    device=device,
    dtype=dtype,
)
```

---

## 4. `cache.get()` 每次都 clone 整段缓存

```python
return cached_slice.clone()
```

这会在每层、每个 decode step 中复制全部历史 K/V。

它避免外部原地修改缓存，但会带来较大的复制开销。真正强调高性能的实现通常直接返回切片 view：

```python
return (
    self.keys[layer_idx, :, :, :end, :],
    self.values[layer_idx, :, :, :end, :],
)
```

只要后续代码不对返回值做原地修改即可。

---

最关键的执行链可以记成：

```text
Prompt: A B C

Prefill:
A B C → cache[A,B,C] → logits → sample D

Decode 1:
输入 D → cache[A,B,C,D] → logits → sample E

Decode 2:
输入 E → cache[A,B,C,D,E] → logits → sample F
```

而采样链是：

```text
logits
  ↓ temperature 调整尖锐程度
  ↓ top-k 固定候选数量
  ↓ top-p 动态候选集合
  ↓ softmax 转成概率
  ↓ multinomial 随机抽取
```
