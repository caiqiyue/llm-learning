# 第 5 章：GPT-2 强化学习 PPO 总结

先记住一句总纲：

```text
PPO 阶段 = 让 GPT-2 自己生成回答，Reward Model 打分，
然后 GPT-2 根据分数调整自己，让以后更容易生成高分回答。
```

它和前面几个阶段的关系是：

```text
Pretrain：学会语言是什么
SFT：学会按照 prompt 回答
Reward Model：学会判断哪个回答更好
PPO：让模型自己生成回答，用 Reward Model 的分数继续优化 policy
```

---

# 1. 为什么 SFT 之后还要 PPO？

SFT 的训练方式是：

```text
给 prompt 和标准 response，让模型模仿标准答案。
```

例如：

```text
prompt:
Tell me a story.

response:
The fox met an owl.
```

SFT 学的是：

```text
看到 Tell me a story. 之后，生成 The fox met an owl.
```

但是 SFT 有一个局限：

```text
它只能模仿训练数据里的答案。
```

如果你想进一步优化模型，让它：

```text
更符合人类偏好
更有帮助
更安全
更清楚
更不胡说
```

就需要 Reward Model 来告诉模型：

```text
这个回答好不好。
```

于是 PPO 阶段的目标变成：

```text
让 GPT-2 生成 Reward Model 更喜欢的回答。
```

---

# 2. GPT-2 的强化学习到底是什么？

强化学习里有几个核心概念：


| 强化学习概念 | GPT-2 里的对应                             |
| ------------ | ------------------------------------------ |
| state        | 当前已有文本，也就是 prompt + 已生成 token |
| action       | 下一个 token                               |
| policy       | 正在训练的 GPT-2                           |
| reward       | Reward Model 分数 + KL 惩罚                |
| episode      | 从 prompt 开始生成完整 response 的过程     |
| value        | 当前状态未来大概能拿多少 reward            |
| advantage    | 当前 token 比预期好多少                    |

比如 prompt 是：

```text
Tell me a story.
```

GPT-2 生成：

```text
The fox met an owl.
```

这个过程可以拆成：

```text
状态 0：Tell me a story.
动作 0：The

状态 1：Tell me a story. The
动作 1：fox

状态 2：Tell me a story. The fox
动作 2：met

状态 3：Tell me a story. The fox met
动作 3：an

状态 4：Tell me a story. The fox met an
动作 4：owl
```

所以 GPT-2 强化学习的本质是：

```text
每一步选择一个 token；
最后组成完整回答；
Reward Model 给整段回答打分；
模型根据分数调整以后选择 token 的概率。
```

---

# 3. PPO 阶段的 4 个模型

PPO 阶段通常同时有 4 个角色。

## 3.1 policy：正在训练的 GPT-2

policy 就是当前要优化的模型。

它通常从 SFT 权重初始化：

```text
policy = SFT 后的 GPT-2
```

它负责生成回答。

例如：

```text
prompt:
Tell me a story.

policy 生成:
The fox met an owl.
```

PPO 阶段真正要训练的就是 policy。

```text
policy：训练
```

---

## 3.2 ref\_model：冻结的参考模型

ref\_model 也是 SFT 后的 GPT-2。

但是它被冻结，不训练。

```text
ref_model = SFT 后的 GPT-2
```

它的作用是：

```text
防止 policy 为了讨好 Reward Model 而跑偏。
```

比如 policy 为了刷 RM 分数，可能开始输出奇怪文本：

```text
Excellent excellent excellent excellent...
```

如果 RM 不够完美，可能误判这种回答很好。

所以 ref\_model 用来提醒 policy：

```text
你可以变好，但不要离原来的 SFT 模型太远。
```

这个限制就是 KL 惩罚。

```text
ref_model：冻结
```

---

## 3.3 reward\_model：冻结的裁判

reward\_model 是前面训练好的 RM。

它输入：

```text
prompt + response
```

输出：

```text
一个 scalar reward 分数
```

例如：

```text
RM("Tell me a story. The fox met an owl.") = 2.0
```

它只负责打分，不负责生成文本。

PPO 阶段 reward\_model 是冻结的。

```text
reward_model：冻结
```

---

## 3.4 value\_head：价值头

value\_head 是挂在 policy 后面的一个小线性层。

通常类似：

```python
policy.value_head = nn.Linear(n_embd, 1)
```

它不是一个完整独立的大模型，而是：

```text
GPT-2 backbone 后面的一个小预测头。
```

GPT-2 每个 token 位置会输出 hidden state：

```text
hidden_states.shape = [B, T, n_embd]
```

value\_head 把每个位置的 hidden state 变成一个 scalar：

```text
values.shape = [B, T]
```

它预测的是：

```text
当前这个位置继续生成下去，未来大概能拿多少 reward。
```

例如：

```text
Tell me a story.        -> value = 0.6
Tell me a story. The    -> value = 0.8
Tell me a story. The fox -> value = 1.1
```

value\_head 是需要训练的。

```text
value_head：训练
```

---

# 4. Rollout：让 policy 自己生成回答

Rollout 的意思是：

```text
让当前 policy 实际生成一批 response，收集训练经验。
```

例如采样一批 prompt：

```text
prompt 1: Tell me a story.
prompt 2: What is 1+1?
prompt 3: Describe a cat.
```

policy 自己生成回答：

```text
response 1: The fox met an owl.
response 2: 1+1 equals 2.
response 3: A cat is a small animal.
```

这一步不是训练，而是收集数据。

代码类似：

```python
with torch.no_grad():
    responses = policy.batched_generate(
        prompts,
        max_new_tokens=64,
        do_sample=True,
        temperature=1.0,
    )
```

Rollout 阶段要记录几个东西：

```text
full_ids：prompt + response 的完整 token ids
old_logprobs：生成时旧 policy 对每个 token 的 log 概率
old_values：生成时 value_head 对每个位置的 value 预测
rewards：后面根据 RM 和 KL 计算出来的 token-level reward
```

---

# 5. old\_logprobs 是什么？

GPT-2 生成每个 token 时，会给整个词表一个概率分布。

比如当前状态是：

```text
Tell me a story.
```

模型可能给出：

```text
The: 0.30
A: 0.15
Once: 0.10
Dog: 0.02
...
```

如果采样到了：

```text
The
```

那么这个动作的概率是：

```text
P(The | Tell me a story.) = 0.30
```

logprob 就是：

```text
log(0.30)
```

old\_logprobs 记录的是：

```text
rollout 生成时，旧 policy 对自己生成出来的 token 的 log 概率。
```

为什么要记录？

因为 PPO 后面要比较：

```text
新 policy 和旧 policy 对同一个 token 的概率变化了多少。
```

这个变化就是 ratio。

---

# 6. Reward 怎么算？

PPO 的 reward 由两部分组成：

```text
最终 reward = Reward Model 分数 - KL 惩罚
```

更具体一点：

```text
每个 token 位置都有 KL 惩罚；
最后一个 token 位置额外加上 RM 对整句的分数。
```

---

## 6.1 RM 给整句打分

完整回答：

```text
Tell me a story. The fox met an owl.
```

Reward Model 输出：

```text
r_total = 2.0
```

这个分数是对整句 response 的评价。

---

## 6.2 KL 惩罚

KL 惩罚的作用是：

```text
防止 policy 偏离 SFT 模型太远。
```

对同一个 token，比较 policy 和 ref\_model 的 logprob：

```python
logp_policy = compute_logp(policy, full_ids)
logp_ref = compute_logp(ref_model, full_ids)

kl = logp_policy - logp_ref
```

如果 policy 和 ref\_model 差别很大，就说明 policy 跑偏了。

然后加惩罚：

```python
rewards = -ppo_kl_coef * kl
```

假设：

```text
ppo_kl_coef = 0.1
```

意思是：

```text
偏离越大，扣分越多。
```

---

## 6.3 为什么 RM 分数加到最后一个 token？

因为 RM 是看完整回答后打分。

比如：

```text
The fox met an owl.
```

单看第一个 token：

```text
The
```

很难判断整句好坏。

所以项目里一般这样做：

```python
rewards = -ppo_kl_coef * kl
rewards[:, -1] += r_total
```

含义是：

```text
每个 token 都承受 KL 惩罚；
最后一个 token 额外获得整句 RM 分数。
```

例子：

```text
The  -> -0.02
fox  -> -0.03
met  -> -0.01
an   -> -0.02
owl  -> -0.04 + 2.0
```

---

# 7. value\_head 是什么？

value\_head 预测的是：

```text
当前状态未来大概能拿多少 reward。
```

例如生成到不同位置：

```text
Tell me a story.             V = 0.6
Tell me a story. The         V = 0.8
Tell me a story. The fox     V = 1.1
Tell me a story. The fox met V = 1.3
```

这些 value 是模型自己的预估。

它不是 Reward Model。

区别是：


| 模型          | 输入                       | 输出                        | 是否冻结 |
| ------------- | -------------------------- | --------------------------- | -------- |
| reward\_model | 完整 prompt + response     | 最终 reward 分数            | 冻结     |
| value\_head   | 每个 token 的 hidden state | 每个位置的预期未来收益 V\_t | 训练     |

你可以这样理解：

```text
Reward Model = 老师最后打分
value_head = 学生写到一半时自己估分
```

---

# 8. Advantage 是什么？

Advantage 表示：

```text
当前这个 token 比预期好多少。
```

最简单的理解是：

```text
Advantage = 实际结果 - 原本预期
```

如果：

```text
advantage > 0
```

说明这个 token 比预期好，以后应该提高它的概率。

如果：

```text
advantage < 0
```

说明这个 token 比预期差，以后应该降低它的概率。

---

## 8.1 举例理解

假设最终 RM 分数是：

```text
reward = 2.0
```

value\_head 在某个位置原本预测：

```text
value = 0.8
```

那么：

```text
advantage = 2.0 - 0.8 = +1.2
```

意思是：

```text
实际结果比预期好，这个 token 值得鼓励。
```

如果 value\_head 原本预测：

```text
value = 3.0
```

但实际 reward 只有：

```text
2.0
```

那么：

```text
advantage = 2.0 - 3.0 = -1.0
```

意思是：

```text
虽然 reward 不低，但低于预期，这个 token 表现不如预期。
```

所以 PPO 看的不是单纯的 reward，而是：

```text
比预期好还是差。
```

---

# 9. GAE 是什么？

GAE，全称：

```text
Generalized Advantage Estimation
```

中文叫：

```text
广义优势估计。
```

它的作用是：

```text
用 rewards 和 value_head 的 values，计算每个 token 的 advantage。
```

注意：

```text
value_head 输出的是每个 token 的预期值 V_t；
GAE 输出的是每个 token 的优势 A_t。
```

不是 GAE 计算预期值，而是 GAE 计算 advantage。

---

## 9.1 GAE 的公式

核心公式是：

```text
δ_t = r_t + γ V_{t+1} - V_t
```

```text
A_t = δ_t + γλ A_{t+1}
```

其中：

```text
r_t：当前 token 位置的 reward
V_t：value_head 对当前位置的预估
V_{t+1}：value_head 对下一个位置的预估
γ：未来奖励折扣，一般可以是 1.0
λ：GAE 平滑系数，常见 0.95
```

---

## 9.2 δ\_t 的直觉

```text
δ_t = r_t + γ V_{t+1} - V_t
```

它表示：

```text
走完当前这一步后，实际情况比当前预期好多少。
```

也就是：

```text
当前拿到的 reward
+
下一步还有多少预期收益
-
当前位置原本的预期收益
```

如果 δ\_t 是正的：

```text
这一步比预期好。
```

如果 δ\_t 是负的：

```text
这一步比预期差。
```

---

## 9.3 为什么 A\_t 要从后往前算？

```text
A_t = δ_t + γλ A_{t+1}
```

这说明：

```text
当前位置的好坏，不只看当前位置，还会受到后面结果影响。
```

比如 token：

```text
The
```

单独看不出好坏。

如果后面是：

```text
The fox met an owl.
```

那就不错。

如果后面是：

```text
The the the the the...
```

那就很差。

所以 GAE 会把后面的好坏往前传回来一部分。

---

# 10. GAE 数字例子

假设 policy 生成 3 个 token：

```text
The / fox / owl
```

Reward Model 最后给整句：

```text
r_total = 2.0
```

每个 token 有 KL 惩罚：

```text
The: -0.1
fox: -0.1
owl: -0.1 + 2.0 = 1.9
```

所以：

```text
rewards = [-0.1, -0.1, 1.9]
```

value\_head 预测：

```text
values = [0.5, 0.8, 1.0]
```

假设为了简单：

```text
γ = 1
λ = 1
```

最后一个 token `owl`：

```text
δ_owl = 1.9 + 0 - 1.0 = 0.9
A_owl = 0.9
```

中间 token `fox`：

```text
δ_fox = -0.1 + 1.0 - 0.8 = 0.1
A_fox = 0.1 + 0.9 = 1.0
```

第一个 token `The`：

```text
δ_The = -0.1 + 0.8 - 0.5 = 0.2
A_The = 0.2 + 1.0 = 1.2
```

最后得到：

```text
The: +1.2
fox: +1.0
owl: +0.9
```

意思是：

```text
这几个 token 都比预期好，所以 PPO 会提高它们的概率。
```

---

# 11. returns 是什么？

GAE 算完 advantages 后，还会算：

```text
returns = advantages + values
```

因为：

```text
advantage = return - value
```

所以：

```text
return = advantage + value
```

returns 用来训练 value\_head。

value loss 是：

```python
loss_value = F.mse_loss(values, returns)
```

意思是：

```text
让 value_head 下次预测得更接近真实目标 return。
```

所以：

```text
advantages：给 policy 用，决定 token 概率升还是降
returns：给 value_head 用，训练它预测得更准
```

---

# 12. PPO ratio 是什么？

PPO 更新 policy 时，会重新计算当前新 policy 对这些 token 的概率。

ratio 是：

```text
ratio = 新 policy 概率 / 旧 policy 概率
```

代码里因为用 logprob，所以写成：

```python
ratio = torch.exp(logp_new - old_logprobs)
```

因为：

```text
logp_new - logp_old = log(p_new / p_old)
```

再 exp 回去就是：

```text
p_new / p_old
```

---

## 12.1 举例

rollout 时旧 policy 生成 `fox` 的概率是：

```text
old_prob = 0.20
```

更新后新 policy 对 `fox` 的概率是：

```text
new_prob = 0.24
```

那么：

```text
ratio = 0.24 / 0.20 = 1.2
```

说明：

```text
新模型把 fox 的概率提高到原来的 1.2 倍。
```

如果：

```text
new_prob = 0.90
```

那么：

```text
ratio = 0.90 / 0.20 = 4.5
```

说明：

```text
更新太猛了。
```

---

# 13. PPO clip 是什么？

PPO 的核心是：

```text
可以根据 reward 更新 policy，但不能一次更新太猛。
```

所以它限制 ratio。

如果：

```text
clip_eps = 0.2
```

那么 ratio 的合理范围是：

```text
[1 - 0.2, 1 + 0.2] = [0.8, 1.2]
```

也就是说：

```text
好 token 的概率可以提高，但不要提高太多；
坏 token 的概率可以降低，但不要降低太多。
```

---

# 14. PPO policy loss

PPO 的核心代码是：

```python
ratio = torch.exp(logp_new - old_logprobs)

loss_unclipped = ratio * advantages
loss_clipped = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * advantages

loss_policy = -torch.min(loss_unclipped, loss_clipped).mean()
```

因为 PyTorch 是最小化 loss，所以前面有负号。

PPO 实际上是在最大化：

```text
min(ratio * advantage, clipped_ratio * advantage)
```

这个 min 是一种保守策略：

```text
如果更新太激进，就按 clipped 后的保守值计算。
```

---

# 15. A > 0 时 clip 怎么理解？

假设：

```text
advantage = +1.0
```

说明这个 token 是好动作。

如果：

```text
ratio = 1.1
```

表示概率提高 10%，可以接受。

如果：

```text
ratio = 1.5
```

表示概率提高 50%，太猛。

PPO 会把它最多当成：

```text
ratio = 1.2
```

来计算。

所以：

```text
好 token 可以提高概率，但不能一下子拉太高。
```

---

# 16. A < 0 时 clip 怎么理解？

假设：

```text
advantage = -1.0
```

说明这个 token 是坏动作。

如果：

```text
ratio = 0.9
```

表示概率降低 10%，可以接受。

如果：

```text
ratio = 0.3
```

表示概率降低 70%，太猛。

PPO 会限制它，不让 policy 一下子把这个 token 打死。

所以：

```text
坏 token 可以降低概率，但不能一下子压太狠。
```

---

# 17. PPO 为什么要这么保守？

因为语言模型很容易训练崩。

如果更新太猛，可能出现：

```text
模型开始重复输出
模型为了讨好 RM 说怪话
模型语言能力下降
模型偏离 SFT 风格
reward 突然爆炸
```

PPO 的 clip 就是在做一件事：

```text
每次只允许 policy 小幅进步。
```

这就是 PPO 中 Proximal 的含义：

```text
Proximal = 靠近旧策略，不要离太远。
```

---

# 18. PPO 的总 loss

PPO 训练通常包括两个主要 loss：

```text
policy loss：训练 policy，让高 advantage token 概率上升，低 advantage token 概率下降
value loss：训练 value_head，让它更准确预测未来收益
```

代码类似：

```python
loss_policy = ...
loss_value = F.mse_loss(values, returns)

loss = loss_policy + c1 * loss_value
```

其中：

```text
c1 = 0.5
```

意思是：

```text
value loss 的权重是 0.5。
```

有些实现还会加入 entropy bonus，但你这个项目主要是：

```text
policy loss + value loss
```

---

# 19. Reward Normalization 是什么？

PPO 很容易因为 reward 尺度不稳定而爆炸。

比如 RM 分数一开始是：

```text
[-1, 0, 1]
```

后面突然变成：

```text
[50, 80, 100]
```

那么 advantage 会非常大，policy 更新会非常猛，训练就容易崩。

所以可以做 reward normalization：

```python
r_total = (r_total - r_total.mean()) / (r_total.std() + 1e-8)
```

意思是：

```text
把当前 batch 的 reward 标准化成均值 0、标准差 1。
```

例如原始 reward：

```text
[10, 12, 14, 16]
```

标准化后大概是：

```text
[-1.16, -0.39, 0.39, 1.16]
```

这样 reward 尺度稳定，PPO 更不容易炸。

# 20. PPO 完整流程总结

现在把整个流程串起来。

## 第一步：加载模型

```text
policy：加载 SFT 权重，可训练
ref_model：加载 SFT 权重，冻结
reward_model：加载 RM 权重，冻结
value_head：挂在 policy 上，可训练
```

---

## 第二步：Rollout 生成回答

```text
给一批 prompts；
policy 自己采样生成 responses；
记录 full_ids、old_logprobs、old_values。
```

例子：

```text
prompt:
Tell me a story.

response:
The fox met an owl.
```

---

## 第三步：Reward Model 打分

```text
reward_model 看完整 prompt + response；
输出 r_total。
```

例如：

```text
r_total = 2.0
```

---

## 第四步：计算 KL 惩罚

```text
policy 和 ref_model 都计算这些 token 的 logprob；
如果 policy 偏离 ref_model 太多，就扣 reward。
```

```text
reward = RM 分数 - KL 惩罚
```

---

## 第五步：用 GAE 算 advantage 和 return

输入：

```text
rewards
values
mask
```

输出：

```text
advantages：每个 token 比预期好多少
returns：value_head 的训练目标
```

---

## 第六步：PPO 更新 policy 和 value\_head

重新计算：

```text
logp_new
values_new
```

然后：

```text
ratio = exp(logp_new - old_logprobs)
```

根据：

```text
ratio
advantages
clip_eps
```

计算 policy loss。

再根据：

```text
values
returns
```

计算 value loss。

最后：

```text
loss = loss_policy + 0.5 * loss_value
```

反向传播更新：

```text
policy
value_head
```

不更新：

```text
ref_model
reward_model
```

# 21. 一整个例子完整走一遍

假设 prompt 是：

```text
Tell me a story.
```

policy 生成：

```text
The fox met an owl.
```

完整文本：

```text
Tell me a story. The fox met an owl.
```

---

## 21.1 生成时记录概率

生成时旧 policy 的概率：

```text
The: 0.30
fox: 0.20
met: 0.25
an: 0.40
owl: 0.10
```

记录为：

```text
old_logprobs
```

---

## 21.2 RM 打分

Reward Model 看完整回答：

```text
RM = 2.0
```

说明回答不错。

---

## 21.3 KL 惩罚

每个 token 和 ref\_model 比较，有一些惩罚：

```text
The: -0.02
fox: -0.03
met: -0.01
an: -0.02
owl: -0.04
```

最后一个 token 加 RM 分数：

```text
The: -0.02
fox: -0.03
met: -0.01
an: -0.02
owl: 1.96
```

这就是 token-level rewards。

---

## 21.4 value\_head 预测

value\_head 给每个位置预测：

```text
The: 0.5
fox: 0.8
met: 1.1
an: 1.3
owl: 1.5
```

意思是：

```text
模型预计每个位置之后未来能拿多少分。
```

---

## 21.5 GAE 算 advantage

GAE 根据 rewards 和 values 算出：

```text
The: +1.2
fox: +1.0
met: +0.7
an: +0.5
owl: +0.4
```

说明：

```text
这些 token 都比预期好。
```

所以 PPO 会提高这些 token 的概率。

---

## 21.6 PPO 更新概率，但 clip 限制幅度

比如 token `fox`：

```text
old_prob = 0.20
```

如果新 policy 变成：

```text
new_prob = 0.24
```

ratio：

```text
0.24 / 0.20 = 1.2
```

可以接受。

如果新 policy 想变成：

```text
new_prob = 0.90
```

ratio：

```text
0.90 / 0.20 = 4.5
```

太猛，会被 PPO clip 限制。

所以 PPO 的作用是：

```text
确实提高好 token 的概率，但不要一下子提高太夸张。
```

# 22. 和 SFT 的区别

SFT 是：

```text
给定标准答案，逐 token 模仿。
```

例如：

```text
Tell me a story. <sep> The fox met an owl.
```

模型训练目标是：

```text
<sep> -> The
The -> fox
fox -> met
met -> an
an -> owl
```

这是有标准答案的。

---

PPO 是：

```text
没有标准答案。
```

模型自己生成：

```text
The fox met an owl.
```

然后 RM 打分。

如果高分，PPO 提高这条生成路径的概率。

如果低分，PPO 降低这条生成路径的概率。

所以：

```text
SFT 是“照答案学”；
PPO 是“自己答题，老师打分，然后根据分数改进”。
```

# 23. PPO 里几个核心词的最简解释

## policy

```text
正在训练的 GPT-2，负责生成回答。
```

## ref\_model

```text
冻结的 SFT GPT-2，用来防止 policy 跑偏。
```

## reward\_model

```text
冻结的奖励模型，用来给完整回答打分。
```

## value\_head

```text
挂在 policy 上的小线性头，预测每个 token 位置未来大概能拿多少 reward。
```

## rollout

```text
让 policy 自己生成一批回答。
```

## reward

```text
Reward Model 分数，加上 KL 惩罚之后的训练反馈。
```

## value

```text
value_head 对未来收益的预测。
```

## advantage

```text
实际结果比 value_head 预期好多少。
```

## GAE

```text
用 rewards 和 values，反向递推计算每个 token 的 advantage。
```

## ratio

```text
新 policy 对 token 的概率 / 旧 policy 对 token 的概率。
```

## clip

```text
限制 ratio 不要离 1 太远，防止 policy 更新太猛。
```

# 24. 最关键公式整理

## Reward 构造

```text
rewards = -kl_coef * KL
```

最后一个 token 加 RM 分数：

```text
rewards[:, -1] += r_total
```

---

## KL 简化估计

```text
kl = logp_policy - logp_ref
```

---

## GAE

```text
δ_t = r_t + γ V_{t+1} - V_t
```

```text
A_t = δ_t + γλ A_{t+1}
```

---

## Return

```text
returns = advantages + values
```

---

## PPO ratio

```text
ratio = exp(logp_new - old_logprobs)
```

也就是：

```text
ratio = p_new / p_old
```

---

## PPO clipped objective

```text
loss_unclipped = ratio * advantages
```

```text
loss_clipped = clip(ratio, 1 - eps, 1 + eps) * advantages
```

```text
loss_policy = -mean(min(loss_unclipped, loss_clipped))
```

---

## Value loss

```text
loss_value = MSE(values, returns)
```

---

## 总 loss

```text
loss = loss_policy + c1 * loss_value
```

---

# 25. 最终一句话总结

GPT-2 的 PPO 强化学习可以理解成：

```text
policy 自己生成回答；
reward_model 给整句回答打分；
ref_model 约束 policy 不要偏离 SFT 太远；
value_head 预测每个位置未来能拿多少分；
GAE 计算每个 token 比预期好还是差；
PPO 根据 advantage 调整 token 概率；
clip 限制调整幅度，防止一次更新太猛。
```

再压缩成最短版本：

```text
SFT 是模仿标准答案；
RM 是学会打分；
PPO 是自己生成答案，让 RM 打分，然后小步更新 policy。
```

你现在理解 PPO 时，只要抓住这条主线就够了：

```text
生成 → 打分 → 算每个 token 的好坏 → 调整 token 概率 → 限制别调太猛
```
