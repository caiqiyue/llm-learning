Weight Tying 可以理解成一句话：

**输入 token 用的“词向量表”和输出预测 token 用的“分类器权重表”，直接共用同一张表。**

也就是：

```python
self.head.weight = self.tok_emb.weight
```

不是复制一份，而是让它们**指向同一个参数矩阵**。

---

# 1. 先看没有 Weight Tying 的情况

假设你的模型里有两个东西：

```python
self.tok_emb = nn.Embedding(vocab_size, n_embd)
self.head = nn.Linear(n_embd, vocab_size, bias=False)
```

其中：

```text
vocab_size = 45
n_embd = 128
```

那么：

```text
tok_emb.weight.shape = [45, 128]
head.weight.shape    = [45, 128]
```

注意，二者形状刚好一样。

---

## tok\_emb 是干什么的？

`tok_emb` 是输入层。

它做的是：

```text
token id -> token embedding
```

比如：

```python
idx = 23
```

那么：

```python
x = self.tok_emb(idx)
```

本质上是在查表：

```text
取出 tok_emb.weight[23]
```

也就是：

```text
第 23 个 token 对应的 128 维向量
```

所以输入 embedding 矩阵可以理解成：

```text
token 0  -> 一个 128 维向量
token 1  -> 一个 128 维向量
token 2  -> 一个 128 维向量
...
token 23 -> 一个 128 维向量
...
token 44 -> 一个 128 维向量
```

---

## lm\_head 是干什么的？

`lm_head` 是输出层。

它做的是：

```text
hidden state -> vocab 上每个 token 的分数
```

比如 Transformer 最后输出一个 hidden vector：

```text
h.shape = [128]
```

然后：

```python
logits = self.head(h)
```

输出：

```text
logits.shape = [45]
```

意思是：

```text
第 0 个 token 的分数
第 1 个 token 的分数
第 2 个 token 的分数
...
第 23 个 token 的分数
...
第 44 个 token 的分数
```

然后经过 softmax 变成概率分布。

---

# 2. 所以问题来了：为什么这两个矩阵可以共享？

因为它们形状刚好一样：

```text
tok_emb.weight: [vocab_size, n_embd]
head.weight:    [vocab_size, n_embd]
```

一个用于输入查表。

一个用于输出分类。

虽然用法不同，但每一行都对应同一个 token。

比如：

```text
tok_emb.weight[23] 表示 token 23 的输入语义向量
head.weight[23]    表示预测 token 23 时使用的输出分类向量
```

Weight Tying 的想法就是：

```text
既然它们都在描述 token 23，那为什么要学两套？
直接用同一套不就行了？
```

于是：

```python
self.head.weight = self.tok_emb.weight
```

这样：

```text
tok_emb.weight[23] 和 head.weight[23] 是同一个向量
```

---

# 3. 用一个小例子讲清楚

假设词表只有 4 个 token：

```text
0 -> 我
1 -> 喜欢
2 -> 猫
3 -> 狗
```

embedding 维度是 3。

那么 `tok_emb.weight` 可能是：

```text
             dim1   dim2   dim3
我      ->   0.2    0.1   -0.3
喜欢    ->   0.4   -0.5    0.7
猫      ->   0.8    0.6    0.1
狗      ->   0.7    0.5    0.2
```

如果输入是：

```text
猫
```

token id 是：

```text
2
```

那么 embedding 层直接查：

```text
tok_emb.weight[2] = [0.8, 0.6, 0.1]
```

这就是“猫”的输入向量。

---

然后模型经过 Transformer 后，某个位置输出 hidden state：

```text
h = [0.75, 0.55, 0.15]
```

现在模型要预测下一个 token 是什么。

如果用了 Weight Tying，那么输出层会拿这个 `h` 和每个 token 的 embedding 做相似度计算：

```text
logit(我)   = h · E_我
logit(喜欢) = h · E_喜欢
logit(猫)   = h · E_猫
logit(狗)   = h · E_狗
```

也就是：

```text
当前 hidden state 和哪个 token 的 embedding 更像，
哪个 token 的输出分数就更高。
```

如果 `h` 很像“猫”的向量，那么：

```text
logit(猫)
```

就会比较大。

如果 `h` 很像“狗”的向量，那么：

```text
logit(狗)
```

就会比较大。

这就是你笔记里说的：

```text
输入 token 的向量 = 输出 token 概率分布的对偶
```

换成人话就是：

```text
一个 token 作为输入时，有自己的语义向量；
模型想输出这个 token 时，也应该用同一个语义向量去匹配。
```

---

# 4. 从矩阵乘法角度看

Embedding 矩阵是：

```text
E.shape = [vocab_size, n_embd]
```

输入时：

```text
token id = 23
```

就是查：

```text
E[23]
```

输出时，Transformer 给你一个 hidden state：

```text
h.shape = [n_embd]
```

要得到所有 token 的分数：

```text
logits = h @ E.T
```

因为：

```text
h.shape   = [n_embd]
E.T.shape = [n_embd, vocab_size]
```

所以：

```text
logits.shape = [vocab_size]
```

也就是每个 token 一个分数。

所以 Weight Tying 的本质公式是：

```text
logit_j = h · E_j
```

其中：

```text
E_j 是第 j 个 token 的 embedding 向量
```

这句话非常重要。

它表示：

```text
模型最后的 hidden state 和哪个 token 的 embedding 越接近，
哪个 token 的预测分数就越高。
```

---

# 5. 为什么能减少参数量？

如果不共享：

```text
tok_emb.weight: 45 × 128 = 5760
head.weight:    45 × 128 = 5760
```

总共：

```text
11520 个参数
```

如果共享：

```text
tok_emb.weight 和 head.weight 是同一个矩阵
```

就只需要：

```text
5760 个参数
```

节省：

```text
5760 个参数
```

在你这个小项目里看起来不大。

但真实 GPT-2 里：

```text
vocab_size = 50257
n_embd = 768
```

单个矩阵参数量大约是：

```text
50257 × 768 ≈ 3860 万
```

如果不共享，输入 embedding 和输出 head 各一份，就会多出三千多万参数。

所以 Weight Tying 在大模型里是很有意义的。

---

# 6. 为什么说它能保持语义一致？

假设 token 23 表示：

```text
好
```

如果没有 Weight Tying，模型会有两套向量：

```text
输入“好”时用：tok_emb.weight[23]
输出“好”时用：head.weight[23]
```

这两套向量是分别训练的。

可能出现一种情况：

```text
输入侧的“好”学到了一种语义空间
输出侧的“好”又学到另一种语义空间
```

当然模型也能训练，但有些冗余。

Weight Tying 强制它们使用同一套表示：

```text
输入“好”的向量
=
输出“好”的分类向量
```

这样模型的输入空间和输出空间更一致。

也就是说：

```text
模型读到“好”时用的语义表示，
和模型想生成“好”时用的语义表示，
是同一个。
```

这就是“语义一致”。

---

# 7. 你可以用“查字典”和“反向查字典”理解

输入 embedding 像是：

```text
看到 token id，查它的语义向量
```

例如：

```text
23 -> “好”的向量
```

输出 lm\_head 像是：

```text
看到一个 hidden state，判断它最像哪个 token 的向量
```

例如：

```text
hidden state 很像“好”的向量
=> 输出 token 23 的概率高
```

所以它们刚好是两个方向：

```text
输入：token id -> 向量
输出：向量 -> token 分数
```

Weight Tying 就是让这两个方向共用同一套 token 向量表。

---

# 8. 代码里到底发生了什么？

原来是两套参数：

```python
self.tok_emb = nn.Embedding(vocab_size, n_embd)
self.head = nn.Linear(n_embd, vocab_size, bias=False)
```

然后：

```python
self.head.weight = self.tok_emb.weight
```

这行代码的意思是：

```text
让 head.weight 不再使用自己原来的参数，
而是直接引用 tok_emb.weight。
```

之后：

```python
self.head.weight is self.tok_emb.weight
```

结果是：

```text
True
```

也就是说，它们不是数值相等那么简单，而是同一个对象。

所以训练时：

```text
tok_emb.weight 被更新
head.weight 也同步更新
```

因为它们本来就是同一个东西。

---

# 9. 训练时梯度怎么走？

用了 Weight Tying 后，这个共享矩阵会收到两部分梯度：

第一部分来自输入侧：

```text
token embedding 参与了 Transformer 的前向传播
loss 反传回来，会更新这些 token 的 embedding
```

第二部分来自输出侧：

```text
lm_head 负责预测下一个 token
softmax + cross entropy 的梯度也会更新这个矩阵
```

因为它们共享，所以同一个矩阵同时被两种信号训练：

```text
作为输入时，要能表达 token 语义；
作为输出时，要能被 hidden state 匹配出来。
```

这反而通常是有益的。

---

# 10. 注意：共享的是 weight，不是功能

这点很重要。

`tok_emb` 和 `head` 的功能不一样。

```python
self.tok_emb(idx)
```

做的是查表：

```text
输入 token id，输出 embedding 向量
```

而：

```python
self.head(x)
```

做的是线性投影：

```text
输入 hidden vector，输出 vocab logits
```

它们只是**共用了同一个参数矩阵**，不是说它们变成同一个层了。

也就是说：

```text
tok_emb：用矩阵的某一行
head：用整个矩阵和 hidden state 做点积
```

---

# 11. 最核心的直觉

假设模型最后 hidden state 是：

```text
h
```

模型要预测下一个词。

如果下一个词应该是“猫”，那模型就应该把 `h` 变得接近“猫”的 embedding。

于是：

```text
h · E_猫
```

会很大。

经过 softmax 后，“猫”的概率就高。

这就是语言模型输出的本质：

```text
预测下一个 token = 在 embedding 空间里找最匹配的 token
```

Weight Tying 让这个逻辑更直接。

---

# 12. 最后总结

Weight Tying 的意思是：

```text
让输入 token embedding 矩阵和输出 lm_head 矩阵共享同一套参数。
```

代码：

```python
self.head.weight = self.tok_emb.weight
```

含义：

```text
lm_head.weight 和 tok_emb.weight 指向同一个 tensor。
```

它的作用：

```text
1. 减少参数量
2. 让输入 token 表示和输出 token 表示保持一致
3. 让 hidden state 通过和 token embedding 做相似度来预测下一个 token
```

你可以这样记：

```text
tok_emb：把 token id 变成向量
lm_head：把向量变成 token 分数
Weight Tying：这两个过程共用同一张 token 向量表
```

最重要的一句话：

```text
输入时，第 23 个 token 查的是 tok_emb.weight[23]；
输出时，模型预测第 23 个 token 的分数，本质上也是 hidden state 和 tok_emb.weight[23] 做相似度。
```

这就是 Weight Tying。
