`model.train()` 在 PyTorch 里不是“开始训练”的意思。

它真正的意思是：

```python
model.train()
```

**把模型切换到训练模式。**

对应地：

```python
model.eval()
```

**把模型切换到评估 / 测试 / 推理模式。**

PyTorch 官方文档里说，`Module.train(mode=True)` 会把模块设置为 training mode；这个开关只会影响某些模块，比如 `Dropout`、`BatchNorm` 等。`eval()` 等价于 `train(False)`。([PyTorch Docs](https://docs.pytorch.org/docs/stable/generated/torch.nn.Module.html?utm_source=chatgpt.com "Module — PyTorch 2.12 documentation"))

---

# 1. `model.train()` 不会自动训练

很多初学者容易误会：

```python
model.train()
```

看起来像“训练模型”。

但它不会自动做这些事情：

```text
不会自动前向传播
不会自动计算 loss
不会自动 backward
不会自动 optimizer.step()
```

真正训练模型的是这一整套流程：

```python
model.train()

for x, y in train_loader:
    optimizer.zero_grad(set_to_none=True)

    logits = model(x)
    loss = criterion(logits, y)

    loss.backward()
    optimizer.step()
```

这里：

```python
model.train()
```

只是告诉模型：

```text
接下来我要训练了，请 Dropout、BatchNorm 等层按训练模式运行。
```

---

# 2. `model.eval()` 也不会自动测试

同理：

```python
model.eval()
```

也不是“自动开始测试”。

它只是告诉模型：

```text
接下来我要评估/推理了，请某些层按评估模式运行。
```

真正的测试流程一般是：

```python
model.eval()

with torch.no_grad():
    for x, y in val_loader:
        logits = model(x)
        loss = criterion(logits, y)
```

注意这里通常还会加：

```python
with torch.no_grad():
```

因为评估时不需要计算梯度。

---

# 3. `model.train()` 控制的到底是什么？

每个 `nn.Module` 里面都有一个状态：

```python
self.training
```

当你调用：

```python
model.train()
```

内部会把：

```python
model.training = True
```

并且递归地把所有子模块也切到训练模式。

当你调用：

```python
model.eval()
```

内部等价于：

```python
model.train(False)
```

也就是：

```python
model.training = False
```

PyTorch 的 C++ 文档也明确说，每个 Module 都有一个布尔值，用来表示当前是 training mode 还是 evaluation mode，这个属性会被某些具体模块用来改变运行行为，比如 BatchNorm 和 Dropout。([PyTorch Docs](https://docs.pytorch.org/cppdocs/api/nn/index.html?utm_source=chatgpt.com "Neural Network Modules (torch::nn)"))

---

# 4. 哪些层会受影响？

最典型的是两个：

```text
Dropout
BatchNorm
```

不是所有层都会受影响。

比如：

```text
Linear
Conv2d
Embedding
ReLU
LayerNorm
```

这些层在 `train()` 和 `eval()` 下通常行为一样。

# 5. Dropout 在 train / eval 下的区别

Dropout 的作用是训练时随机丢掉一部分神经元，防止模型过拟合。

比如：

```python
dropout = nn.Dropout(p=0.5)
```

意思是训练时随机把 50% 的元素变成 0。

## 训练模式

```python
model.train()
```

Dropout 会生效。

比如输入：

```text
[1, 2, 3, 4]
```

可能输出：

```text
[0, 4, 0, 8]
```

注意 PyTorch 的 Dropout 在训练时不仅会把部分元素置 0，还会对保留下来的元素按 `1 / (1 - p)` 放大；官方文档说明，Dropout 在训练时会随机把输入元素置零，并且训练时会按这个比例缩放输出。([PyTorch Docs](https://docs.pytorch.org/docs/stable/generated/torch.nn.Dropout.html?utm_source=chatgpt.com "Dropout — PyTorch 2.12 documentation"))

如果 `p=0.5`，保留下来的值会乘以：

```text
1 / (1 - 0.5) = 2
```

所以：

```text
[1, 2, 3, 4]
```

可能变成：

```text
[0, 4, 0, 8]
```

## 评估模式

```python
model.eval()
```

Dropout 不再随机丢弃元素。

输入：

```text
[1, 2, 3, 4]
```

输出就是：

```text
[1, 2, 3, 4]
```

PyTorch 文档也说，Dropout 在 evaluation 阶段相当于 identity function，也就是基本不改变输入。([PyTorch Docs](https://docs.pytorch.org/docs/stable/generated/torch.nn.Dropout.html?utm_source=chatgpt.com "Dropout — PyTorch 2.12 documentation"))

---

# 6. BatchNorm 在 train / eval 下的区别

BatchNorm 更容易让人困惑。

BatchNorm 在训练时，会用**当前 batch 的均值和方差**来归一化，并且更新自己的 running statistics：

```text
running_mean
running_var
```

在评估时，它不会再用当前 batch 的统计量，而是使用训练期间积累下来的：

```text
running_mean
running_var
```

所以：

```python
model.train()
```

BatchNorm 行为是：

```text
使用当前 batch 的 mean/var
更新 running_mean/running_var
```

而：

```python
model.eval()
```

BatchNorm 行为是：

```text
使用训练时累计的 running_mean/running_var
不再更新它们
```

这就是为什么测试/推理时必须调用：

```python
model.eval()
```

否则 BatchNorm 会继续根据测试数据的 batch 统计量改变行为，测试结果可能不稳定。

# 7. 一个极小例子：Dropout

```python
import torch
import torch.nn as nn

model = nn.Sequential(
    nn.Linear(4, 4),
    nn.Dropout(p=0.5)
)

x = torch.ones(1, 4)

model.train()
print(model(x))
print(model(x))

model.eval()
print(model(x))
print(model(x))
```

训练模式下：

```python
model.train()
```

两次输出可能不一样，因为 Dropout 随机丢神经元。

评估模式下：

```python
model.eval()
```

两次输出通常一样，因为 Dropout 关闭了。

# 8. `model.train()` 和 `torch.no_grad()` 是两回事

这是一个很重要的区别。

```python
model.train()
```

控制的是：

```text
Dropout / BatchNorm 等层的行为
```

而：

```python
with torch.no_grad():
```

控制的是：

```text
是否记录计算图，是否计算梯度
```

它们不是一回事。

所以评估时通常两个都要写：

```python
model.eval()

with torch.no_grad():
    logits = model(x)
```

为什么？

```python
model.eval()
```

让 Dropout、BatchNorm 按推理模式工作。

```python
with torch.no_grad():
```

让 PyTorch 不记录梯度，节省显存和计算。

PyTorch 文档也提醒，`inference_mode` / 禁用梯度这类机制不会自动把模型切到 eval；为了正确推理行为，比如关闭 Dropout、让 BatchNorm 使用 running statistics，仍然需要显式调用 `model.eval()`。([PyTorch Docs](https://docs.pytorch.org/docs/stable/generated/torch.autograd.grad_mode.inference_mode.html?utm_source=chatgpt.com "inference_mode — PyTorch 2.12 documentation"))

# 9. 训练和测试的标准写法

## 训练阶段

```python
model.train()

for input_ids, labels in train_loader:
    optimizer.zero_grad(set_to_none=True)

    outputs = model(input_ids)
    loss = criterion(outputs, labels)

    loss.backward()
    optimizer.step()
```

含义是：

```text
model.train()
让模型进入训练模式

loss.backward()
计算梯度

optimizer.step()
更新参数
```

---

## 验证 / 测试阶段

```python
model.eval()

total_loss = 0

with torch.no_grad():
    for input_ids, labels in val_loader:
        outputs = model(input_ids)
        loss = criterion(outputs, labels)
        total_loss += loss.item()
```

含义是：

```text
model.eval()
让模型进入评估模式

torch.no_grad()
不计算梯度，节省显存

不调用 loss.backward()
不调用 optimizer.step()
所以参数不会更新
```

# 10. 对 GPT-2 来说有什么影响？

GPT-2 里面通常有 Dropout。

所以：

```python
model.train()
```

训练时 Dropout 开启，模型每次前向传播带一点随机扰动，有助于正则化。

```python
model.eval()
```

推理或验证时 Dropout 关闭，输出更稳定。

如果你验证 GPT-2 时忘了写：

```python
model.eval()
```

可能会出现：

```text
同一个输入，每次输出结果不完全稳定
validation loss 有随机波动
生成文本结果不稳定
```

如果你训练前忘了切回：

```python
model.train()
```

那么 Dropout 可能一直关闭，训练行为和预期不一致。

# 11. 最容易混淆的一句话

这三件事分别负责不同事情：

```python
model.train()
```

控制模型内部某些层按训练模式运行。

```python
model.eval()
```

控制模型内部某些层按评估模式运行。

```python
with torch.no_grad():
```

控制不要计算梯度。

它们不是互相替代关系。

---

一句话总结：

**`model.train()` 只是把模型切到训练模式，让 Dropout、BatchNorm 等层按训练规则工作；真正的训练还需要 forward、loss、backward、optimizer.step。`model.eval()` 则把模型切到测试/推理模式，但通常还要配合 `torch.no_grad()` 才能省显存、避免计算梯度。**
