# 二、预训练：Cross-Entropy Loss

代码中模型返回：

```python
_, loss, _ = model(vx, targets=vy)
```

GPT-2 的任务是：

> 给定前面的 token，预测下一个 token。

假设真实目标 token 是 (y\_t)，模型对它预测的概率为：

[
P(y\_t\\mid y\_{<t})
]

单个 token 的负对数似然是：

[
\\ell\_t=-\\log P(y\_t\\mid y\_{<t})
]

整个验证集上，平均交叉熵为：

# [

L\_{\\mathrm{CE}}

-\\frac{1}{N}
\\sum\_{t=1}^{N}
\\log P(y\_t\\mid y\_{<t})
]

其中：

* (N)：有效 token 数；
* (P(y\_t\\mid y\_{<t}))：模型给真实下一个 token 的概率；
* 使用自然对数，因此单位通常称为 `nats`。

代码中的加权平均：

```python
total_loss += loss.item() * n
total_tokens += n

avg_loss = total_loss / total_tokens
```

这是为了避免不同 batch 的有效 token 数不同。

## 含义

假设真实 token 的预测概率为：

```text
模型 A：0.8
模型 B：0.1
```

它们的 loss：

[
-\\log(0.8)\\approx0.223
]

[
-\\log(0.1)\\approx2.303
]

模型越确信正确答案，loss 越小。

因此：

> **Cross-Entropy Loss 越低，说明模型给真实下一个 token 分配的概率越高。**

# 三、预训练：Perplexity 困惑度

代码：

```python
ppl = math.exp(avg_loss)
```

数学公式：

# [

\\mathrm{PPL}

\\exp(L\_{\\mathrm{CE}})
]

展开后：

# [

\\mathrm{PPL}

\\exp\\left(
-\\frac{1}{N}
\\sum\_{t=1}^{N}
\\log P(y\_t\\mid y\_{<t})
\\right)
]

它也等于真实 token 概率几何平均数的倒数：

# [

\\mathrm{PPL}

\\left(
\\prod\_{t=1}^{N}P(y\_t\\mid y\_{<t})
\\right)^{-\\frac1N}
]

## 例子

假设平均 loss 为：

[
L=2
]

那么：

[
\\mathrm{PPL}=e^2\\approx7.39
]

如果 loss 降到：

[
L=1
]

那么：

[
\\mathrm{PPL}=e^1\\approx2.72
]

## 含义

PPL 可以粗略理解为：

> 模型在每一步平均像是在多少个相近候选中犹豫。

例如：

```text
PPL = 20
```

可以直觉地理解成模型每一步的有效候选规模大约是 20。

但这只是直觉解释，不表示模型真的严格从 20 个等概率 token 中挑选。

### 判断方向

[
\\boxed{\\mathrm{PPL越低越好}}
]

但只能在以下条件大致一致时比较：

* 同一个 tokenizer；
* 同一个验证集；
* 相同的数据预处理；
* 相同的 token 粒度。

字符级 tokenizer 的 PPL 不能直接和 GPT-2 BPE tokenizer 的 PPL 比较。

# 四、SFT/PPO：Distinct-n

代码实现的是字符级 n-gram 多样性：

```python
value = len(set(all_ngrams)) / len(all_ngrams)
```

数学公式：

# [

\\mathrm{Distinct}\\text{-}n

\\frac{
\\left|\\mathrm{UniqueNGrams}\_n\\right|
}{
\\left|\\mathrm{AllNGrams}\_n\\right|
}
]

其中：

* 分子：不同 n-gram 的数量；
* 分母：所有 n-gram 出现次数；
* 代码按字符切分，不是按单词切分。

## Distinct-1 例子

假设生成：

```text
cat cat
```

简化成字符：

```text
c, a, t, c, a, t
```

总字符数：

[
6
]

不同字符：

```text
c, a, t
```

数量是：

[
3
]

所以：

# [

\\mathrm{Distinct}\\text{-}1

# \\frac36

0.5
]

## Distinct-2 例子

序列：

```text
abab
```

二元字符组合是：

```text
ab, ba, ab
```

总数为 3，不同组合为：

```text
ab, ba
```

因此：

# [

\\mathrm{Distinct}\\text{-}2

\\frac23
]

## 含义

* 越高：生成内容重复得越少；
* 越低：模型可能总生成相同字符、短语或模板。

通常：

[
\\boxed{\\mathrm{Distinct}\\text{-}n越高，生成越多样}
]

但它不等于质量。

例如随机乱码：

```text
xqzjwv...
```

Distinct-n 可能很高，但内容没有意义。

因此它必须和质量指标一起看。

## 一个重要问题

Distinct-n 对生成长度和样本数量很敏感。

当生成样本越来越多，总 n-gram 数增长，而词表或字符集合有限，Distinct-n 往往自然下降。因此比较两个模型时，应保持：

* prompt 数量一致；
* 最大生成长度一致；
* 采样参数一致。

# 五、SFT：Self-BLEU

Self-BLEU 用来判断不同生成结果之间是否太相似。

普通 BLEU 是：

> 一条模型输出和人工参考答案比较。

Self-BLEU 是：

> 把某一条模型输出作为候选，把模型的其他输出作为参考答案。

代码：

```python
for i, hyp in enumerate(tokenized):
    refs = 所有其他 response
    sentence_bleu(refs, hyp)
```

最后求平均：

# [

\\mathrm{SelfBLEU}

\\frac1M
\\sum\_{i=1}^{M}
\\mathrm{BLEU}
\\left(
x\_i,{x\_j:j\\neq i}
\\right)
]

其中 (M) 是生成样本数量。

## BLEU 的公式

BLEU 的基本形式：

# [

\\mathrm{BLEU}

\\mathrm{BP}
\\cdot
\\exp\\left(
\\sum\_{n=1}^{N}
w\_n\\log p\_n
\\right)
]

其中：

* (p\_n)：修正后的 n-gram 精确率；
* (w\_n)：不同 n-gram 的权重；
* (\\mathrm{BP})：长度惩罚；
* NLTK 默认通常是 BLEU-4，即 (N=4)，每级权重约为 (1/4)。

长度惩罚：

# [

\\mathrm{BP}

\\begin{cases}
1, & c>r\\
\\exp(1-r/c), & c\\le r
\\end{cases}
]

其中：

* (c)：候选文本长度；
* (r)：参考长度。

## 含义

如果所有输出都很像：

```text
The cat runs.
The cat runs.
The cat runs.
```

每一条和其他条都高度重合：

[
\\mathrm{SelfBLEU}\\text{ 高}
]

说明多样性低。

如果输出相差很大：

```text
The cat runs.
A dog sleeps near the lake.
Birds sing in the forest.
```

Self-BLEU 较低，说明输出更丰富。

因此：

[
\\boxed{\\mathrm{SelfBLEU越低，通常表示多样性越高}}
]

它和 Distinct-n 的判断方向相反：

```text
Distinct-n：越高越多样
Self-BLEU：越低越多样
```

但 Self-BLEU 很低同样可能是因为模型在生成随机乱码。

# 六、SFT：Token Entropy

代码计算生成每一步的 next-token 分布熵：

```python
p = softmax(last_logits)
H = -(p * log(p)).sum()
```

数学公式：

# [

H(p)

-\\sum\_{i=1}^{V}p\_i\\log p\_i
]

其中：

* (V)：词表大小；
* (p\_i)：下一个 token 为第 (i) 个词的概率。

之后先对每条生成的所有步骤求平均，再对所有 prompt 求平均。

如果第 (s) 条样本生成了 (T\_s) 步：

# [

H\_s

\\frac1{T\_s}
\\sum\_{t=1}^{T\_s}
\\left(
-\\sum\_{i=1}^{V}p\_{s,t,i}\\log p\_{s,t,i}
\\right)
]

整个评估值：

# [

\\overline H

\\frac1M\\sum\_{s=1}^{M}H\_s
]

## 低熵例子

概率：

```text
A: 0.98
B: 0.01
C: 0.01
```

模型几乎确定选 A，所以熵很低。

## 高熵例子

概率：

```text
A: 0.34
B: 0.33
C: 0.33
```

模型非常不确定，所以熵较高。

## 最大值

当整个词表均匀分布：

[
p\_i=\\frac1V
]

熵最大：

[
H\_{\\max}=\\log V
]

因此也可以进行归一化：

# [

H\_{\\mathrm{normalized}}

\\frac{H}{\\log V}
]

归一化后通常在：

[
[0,1]
]

但当前代码没有归一化。

## 含义

* 熵过低：模型可能过度确定、生成呆板或模式坍缩；
* 熵适中：通常既有一定确定性，也有一定选择空间；
* 熵过高：模型可能不确定、随机性太强、质量不稳定。

所以它不是简单的“越高越好”：

[
\\boxed{\\text{Token Entropy 要结合质量和多样性一起看}}
]

## 当前代码的一个细节

它计算的是：

```python
last_logits = logits / temperature
p = softmax(last_logits)
```

因此 entropy 会受到 `temperature` 影响。

但是它没有在计算熵前应用：

* top-k；
* top-p。

所以这个熵是温度调整后的完整词表分布熵，不是最终经过 top-k/top-p 截断后的采样熵。

# 七、SFT/PPO：Response Quality 规则评分

代码把质量拆成四项，每项 0.25 分。

数学公式可以写成：

# [

Q(r,p)

\\frac14
\\left[
I\_{\\mathrm{length}}
+
I\_{\\mathrm{animal}}
+
I\_{\\mathrm{verb}}
+
I\_{\\mathrm{punctuation}}
\\right]
]

其中指示函数 (I) 满足：

[
I(\\text{条件成立})=1
]

[
I(\\text{条件不成立})=0
]

具体规则：

### 1. 长度

# [

I\_{\\mathrm{length}}

\\mathbf{1}(10\\le |r|\\le50)
]

响应长度在 10～50 字符之间，加 0.25。

### 2. 动物名

# [

I\_{\\mathrm{animal}}

\\mathbf{1}(\\text{response包含动物名})
]

加 0.25。

### 3. 常见动词

# [

I\_{\\mathrm{verb}}

\\mathbf{1}(\\text{response包含指定动词})
]

指定动词包括：

```text
play, run, jump, sleep, sing,
dance, explore, rest, watch, listen
```

### 4. 结尾标点

# [

I\_{\\mathrm{punctuation}}

\\mathbf{1}
\\left(
r\\text{ 以 }.,!,?\\text{ 结尾}
\\right)
]

最终分数可能是：

```text
0.00
0.25
0.50
0.75
1.00
```

整个数据集上的分数：

# [

\\overline Q

\\frac1M\\sum\_{i=1}^{M}Q(r\_i,p\_i)
]

## 含义

它检查的是简单格式和关键词，并不真正理解：

* 回答是否正确；
* 是否与问题相关；
* 是否逻辑连贯；
* 是否存在事实错误。

例如：

```text
The cat cat cat cat run.
```

可能满足长度、动物、动词、标点四项，得到 1.0，但并不是高质量回答。

所以它应该被称为：

> **Toy rule-based quality score，而不是通用语言质量指标。**

## 文档和实现存在一点差异

docstring 写的是：

> 包含 prompt 中提到的动物名。

但实际代码是：

```python
if any(a in resp for a in animals):
```

它只检查回答中是否出现任意动物名，没有检查该动物是否与 prompt 中的动物相同。

更严格的实现应该先从 prompt 找出动物，再检查 response 是否包含同一个动物。

# 八、Reward Model：Pairwise Accuracy

Reward Model 输入一对回答：

* (y\_c)：chosen，人类更喜欢的回答；
* (y\_r)：rejected，人类不喜欢的回答。

Reward Model 分别给出：

[
r\_c=R(x,y\_c)
]

[
r\_r=R(x,y\_r)
]

如果：

[
r\_c>r\_r
]

就认为 Reward Model 排序正确。

成对准确率：

# [

\\mathrm{PairAcc}

\\frac1N
\\sum\_{i=1}^{N}
\\mathbf{1}
\\left(
r\_{c,i}>r\_{r,i}
\\right)
]

## 含义

* `0.5`：在均衡二选一数据上接近随机猜测；
* 高于 `0.5`：学到了一些偏好；
* 越接近 `1.0`：排序能力越强。

代码注释把：

```text
0.7+
```

视为已经学到较明显偏好，但实际合格标准取决于数据难度、噪声和验证集规模。

---

# 九、Reward Model：Bradley–Terry Loss

代码：

```python
bt = -F.logsigmoid(r_c - r_r).mean()
```

单个样本的损失：

# [

L\_{\\mathrm{BT}}

-\\log\\sigma(r\_c-r\_r)
]

其中 sigmoid：

[
\\sigma(z)=\\frac1{1+e^{-z}}
]

Bradley–Terry 模型认为 chosen 胜过 rejected 的概率是：

# [

P(y\_c\\succ y\_r)

\\sigma(r\_c-r\_r)
]

因此损失是：

# [

L\_{\\mathrm{BT}}

-\\log P(y\_c\\succ y\_r)
]

## 例子一：排序正确且差距大

假设：

[
r\_c=3,\\qquad r\_r=0
]

差值：

[
r\_c-r\_r=3
]

概率：

[
\\sigma(3)\\approx0.953
]

损失：

[
-\\log(0.953)\\approx0.049
]

损失很小。

## 例子二：排序错误

假设：

[
r\_c=0,\\qquad r\_r=3
]

差值：

[
-3
]

概率：

[
\\sigma(-3)\\approx0.047
]

损失：

[
-\\log(0.047)\\approx3.049
]

损失很大。

因此：

[
\\boxed{\\mathrm{BT\\ Loss越低越好}}
]

---

# 十、Reward Model：Reward Margin

代码：

```python
margin = mean_r_chosen - mean_r_rejected
```

公式：

# [

\\mathrm{Margin}

\\frac1N
\\sum\_{i=1}^{N}
(r\_{c,i}-r\_{r,i})
]

也等价于：

[
\\overline r\_c-\\overline r\_r
]

## 含义

* Margin 为正：整体上 chosen 的 reward 更高；
* Margin 越大：Reward Model 区分两者的程度通常越强；
* Margin 接近 0：模型难以区分；
* Margin 为负：模型总体排序反了。

但 margin 不能单独使用。

例如模型可能：

* 80% 样本正确且差距较小；
* 20% 样本错误但错误差距非常大。

这时平均 margin 可能不好看，即使准确率还可以。

因此应该同时观察：

```text
pairwise accuracy
Bradley–Terry loss
reward margin
```

另外，Reward Model 的绝对 reward 没有固定物理含义。把所有 reward 同时加 100：

[
r\_c'=r\_c+100
]

[
r\_r'=r\_r+100
]

差值不变，因此 BT loss 和排序结果完全不变。

所以：

> `mean_r_chosen=10` 本身不能说明模型一定很好，关键是相对差值和同一 RM 下的比较。

# 十一、Benchmark：四选一准确率

每道题有四个选项。代码不是让模型生成 `A/B/C/D`，而是分别计算每个选项在题目条件下的对数似然。

假设问题是 (x)，第 (j) 个选项由 token 组成：

[
y^{(j)}=(y\_1^{(j)},\\dots,y\_{T\_j}^{(j)})
]

选项分数：

# [

S\_j

\\log P(y^{(j)}\\mid x)
]

使用自回归展开：

# [

S\_j

\\sum\_{t=1}^{T\_j}
\\log
P
\\left(
y\_t^{(j)}
\\mid
x,y\_{<t}^{(j)}
\\right)
]

代码对应：

```python
token_logps = log_probs.gather(...)
score = token_logps[response_start - 1:].sum()
```

预测：

[
\\hat j=\\arg\\max\_j S\_j
]

准确率：

# [

\\mathrm{Accuracy}

\\frac{
\\text{预测正确题数}
}{
\\text{总题数}
}
]

四选一随机猜测基线：

[
\\frac14=25%
]

## 含义

它衡量模型是否给正确选项分配了最高条件概率。

优点：

* 不依赖随机采样；
* 每次评估较稳定；
* 可以直接比较选项概率。

## 当前实现的长度偏差

它使用总对数概率：

[
S\_j=\\sum\_t\\log P(y\_t\\mid\\cdots)
]

由于每个 log probability 通常小于等于 0，选项越长，累加项越多，分数往往越低。

因此如果选项长度差异较大，模型可能天然偏向短选项。

可以考虑长度归一化：

# [

S\_j^{\\mathrm{avg}}

\\frac1{T\_j}
\\sum\_{t=1}^{T\_j}
\\log P(y\_t^{(j)}\\mid\\cdots)
]

或者使用长度惩罚：

# [

S\_j^{(\\alpha)}

\\frac{
\\sum\_t\\log P(y\_t^{(j)}\\mid\\cdots)
}{
T\_j^\\alpha
}
]

当前代码没有做长度归一化。

# 十二、PPO/SFT 对比：平均 RM Score

代码会用同一个 Reward Model 给 SFT 和 PPO 输出评分：

# [

\\overline R\_{\\mathrm{SFT}}

\\frac1N\\sum\_{i=1}^{N}
R(x\_i,y\_i^{\\mathrm{SFT}})
]

# [

\\overline R\_{\\mathrm{PPO}}

\\frac1N\\sum\_{i=1}^{N}
R(x\_i,y\_i^{\\mathrm{PPO}})
]

提升值：

# [

\\Delta R

## \\overline R\_ {\\mathrm{PPO}}

\\overline R\_{\\mathrm{SFT}}
]

代码：

```python
improvement = ppo_rm - sft_rm
```

## 含义

如果：

[
\\Delta R>0
]

说明按照这个 Reward Model，PPO 输出平均比 SFT 输出更符合偏好。

但这里有一个重要限制：

> PPO 正是在优化 Reward Model 的得分，因此 RM 分数提高不一定等于真实质量提高。

可能发生 reward hacking：

* 输出利用了 RM 的漏洞；
* RM 分数上升；
* 人类实际感受反而下降。

所以应当同时比较：

* RM score；
* benchmark accuracy；
* diversity；
* 长度；
* 人工评估；
* 与参考策略的 KL 距离。

# 十三、PPO：响应长度均值和方差

代码：

```python
mean_len = np.mean(lens)
var_len = np.var(lens)
```

平均长度：

# [

\\mu\_L

\\frac1N
\\sum\_{i=1}^{N}L\_i
]

方差：

# [

\\mathrm{Var}(L)

\\frac1N
\\sum\_{i=1}^{N}
(L\_i-\\mu\_L)^2
]

其中 (L\_i) 是第 (i) 条回答的字符数。

## 含义

平均长度可以发现：

* PPO 是否让回答越来越长；
* 是否出现过短回答；
* 是否总是生成到 `max_new_tokens`；
* Reward Model 是否存在“偏爱长回答”的倾向。

方差可以发现：

* 回答长度是否几乎固定；
* 不同 prompt 下长度是否有适应性；
* 是否存在极短和极长输出混合的问题。

长度本身不是越长越好。

例如 PPO 后：

```text
SFT 平均长度：25
PPO 平均长度：64
```

如果 64 正好是最大生成长度，就需要怀疑模型是否经常无法生成 EOS。

# 十四、推理性能：KV Cache Speedup

代码比较：

* naive generation；
* KV-cache generation。

通常加速比定义为：

# [

\\mathrm{Speedup}

\\frac{
T\_{\\mathrm{naive}}
}{
T\_{\\mathrm{KV}}
}
]

例如：

```text
naive = 120 ms
KV cache = 40 ms
```

那么：

# [

\\mathrm{Speedup}

# \\frac {120} {40}

3
]

表示：

```text
KV-cache 推理约快 3 倍
```

判断：

* `speedup > 1`：KV Cache 更快；
* `speedup = 1`：速度差不多；
* `speedup < 1`：当前实现反而更慢。

不过性能测试必须确保两种生成方式：

* 使用相同 prompt；
* 生成相同 token 数；
* 使用相同设备；
* GPU 上测量前执行同步；
* 包含 warm-up；
* 不把模型加载时间计入；
* 重复多次并取均值或中位数。

# 十五、这些指标之间应该怎样一起看

不能依赖单一指标。

## 预训练阶段

主要观察：

```text
Validation Cross-Entropy ↓
Perplexity ↓
Benchmark Accuracy ↑
```

如果训练 loss 持续下降，但验证 PPL 上升，通常说明过拟合。

## SFT 阶段

建议一起观察：

```text
Distinct-n ↑
Self-BLEU ↓
Token Entropy 适中
Response Quality ↑
Benchmark Accuracy 不明显下降
```

一种可能情况：

```text
Distinct-n 上升
Self-BLEU 下降
Benchmark Accuracy 下降
```

说明模型变得更多样，但可能牺牲了正确性。

## Reward Model 阶段

一起观察：

```text
Pairwise Accuracy ↑
BT Loss ↓
Margin ↑
```

例如：

```text
PairAcc = 0.80
Margin = 0.02
```

说明排序多数正确，但区分信心很弱。

反过来：

```text
PairAcc = 0.55
Margin = 3.0
```

可能是少数极端样本拉高了平均差值，整体排序仍然不好。

## PPO 阶段

当前代码主要看：

```text
RM Score ↑
Response Quality ↑
Distinct-n 不要严重下降
Response Length 不要异常
Benchmark Accuracy 不要严重下降
```

理想情况是 PPO 后：

* RM 分数提高；
* 质量提高；
* 多样性没有完全坍缩；
* 长度没有异常膨胀；
* 基础能力没有明显退化。

# 十六、当前评估代码还缺少的核心 PPO 指标

这份文件虽然能评估输出，但没有包含一些标准 PPO/RLHF 训练诊断指标：

## 1. KL Divergence

衡量 PPO 模型偏离参考 SFT 模型多少：

# [

D\_{\\mathrm{KL}}
(\\pi\_{\\mathrm{PPO}}|\\pi\_{\\mathrm{ref}})

## \\mathbb E\_ {a\\sim\\pi\_{\\mathrm{PPO}}}

\\left[
\\log\\pi\_{\\mathrm{PPO}}(a\\mid s)

\\log\\pi\_{\\mathrm{ref}}(a\\mid s)
\\right]
]

KL 太低：

* PPO 几乎没改变模型。

KL 太高：

* 模型可能偏离语言能力；
* 容易出现 reward hacking 或质量退化。

## 2. Mean Reward

# [

\\overline R

\\frac1N\\sum\_i R\_i
]

应该同时区分：

* 原始 RM reward；
* 加入 KL 惩罚后的总 reward。

## 3. Policy Loss

PPO clipped objective 通常是：

# [

L^{\\mathrm{clip}}

\\mathbb E\_t
\\left[
\\min
\\left(
r\_tA\_t,
\\operatorname{clip}(r\_t,1-\\epsilon,1+\\epsilon)A\_t
\\right)
\\right]
]

其中：

# [

r\_t

\\frac{
\\pi\_\\theta(a\_t\\mid s\_t)
}{
\\pi\_{\\mathrm{old}}(a\_t\\mid s\_t)
}
]

## 4. Value Loss

# [

L\_V

\\frac1N
\\sum\_t
(V\_\\theta(s\_t)-\\hat R\_t)^2
]

## 5. Clip Fraction

# [

\\mathrm{ClipFrac}

\\frac1N
\\sum\_t
\\mathbf1
\\left(
|r\_t-1|>\\epsilon
\\right)
]

它表示多少比例的样本触发了 PPO 截断。

## 6. Explained Variance

# [

\\mathrm{EV}

1-
\\frac{
\\operatorname{Var}(R-V)
}{
\\operatorname{Var}(R)
}
]

用于判断 value model 是否能解释回报变化。

因此，当前代码更偏向：

> **训练完成后的生成质量评估**

还不算完整的：

> **PPO 训练过程健康度监控。**

# 十七、代码中几个值得修正的地方

## 1. `diversity` 分支有变量错误

这里：

```python
r2 = eval_distinct_n(
    args.checkpoint,
    n_gram=2,
    n_samples=50,
    device=device,
)
```

`device` 没有在这个作用域定义，应改为：

```python
device=args.device
```

否则运行：

```bash
python evaluate.py --stage diversity
```

可能报：

```text
NameError: name 'device' is not defined
```

## 2. `n_samples` 在 Pairwise Accuracy 中实际限制的是 batch 数

代码：

```python
for i, vb in enumerate(val_loader):
    if i >= n_samples:
        break
```

这里的 `i` 是 batch 索引，不是样本索引。

因此 `n_samples=200` 实际可能最多评估：

[
200\\times\\mathrm{batch\_size}
]

条样本，而不是 200 条。

更合理的停止条件是根据 `total`：

```python
if total >= n_samples:
    break
```

最后一个 batch 还需要裁剪，才能严格得到 200 个样本。

## 3. PPO 的多样性和质量可能不是基于同一批生成结果

`eval_ppo()` 已经生成了一次：

```python
responses = _generate_responses(...)
```

但随后：

```python
q = eval_response_quality(...)
```

`eval_response_quality()` 会重新加载模型并重新随机生成一次。

因此：

* `distinct_1` 基于第一批采样；
* `response_quality` 基于第二批采样。

更严谨的方式是让两个指标复用同一个 `responses`。

## 4. Benchmark 有长度偏差

前面提到，它使用总 log-likelihood。若选项长度不一致，建议增加平均 log-likelihood 版本。
