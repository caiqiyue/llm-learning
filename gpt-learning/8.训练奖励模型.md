你现在进入的是 RLHF / DPO / PPO 前面的关键步骤：**训练 Reward Model，奖励模型，简称 RM**。

先给你一句总纲：

```text
SFT 让模型学会“怎么回答”；
Reward Model 让模型学会“什么回答更好”。
```

SFT 的数据是：

```text
prompt -> response
```

Reward Model 的数据是：

```text
同一个 prompt 下：
chosen response 比 rejected response 更好
```

也就是偏好数据。

---

# 1. Reward Model 是干什么的？

Reward Model 不负责生成文本。

它负责给一段回答打分。

比如用户问：

```text
Tell me a story.
```

有两个回答：

```text
chosen:
The fox met an owl and they became friends.

rejected:
fox owl story bad.
```

Reward Model 要学会：

```text
score(prompt + chosen) > score(prompt + rejected)
```

也就是：

```text
r_chosen > r_rejected
```

所以 RM 的输出不是 vocab logits，而是一个标量：

```text
reward score = 一个数字
```

例如：

```text
r_chosen = 2.3
r_rejected = -0.8
```

这表示模型认为 chosen 更好。

---

# 2. RM 的数据构造是什么？

SFT 数据是单条：

```python
{
    "prompt": "Tell me a story.",
    "response": "The fox met an owl."
}
```

RM 数据是成对的：

```python
{
    "prompt": "Tell me a story.",
    "chosen": "The fox met an owl and they became friends.",
    "rejected": "fox owl story bad."
}
```

核心含义是：

```text
对于同一个 prompt，人类或者规则认为 chosen 比 rejected 更好。
```

所以 RM 训练的不是“正确答案 token 是什么”，而是：

```text
两个回答谁更好。
```

---

# 3. 为什么 chosen 和 rejected 要共享同一个 prompt？

因为我们比较的是：

```text
在同一个问题下，哪个回答更好。
```

如果 prompt 不一样，就没法公平比较。

比如：

```text
prompt A: Tell me a story.
chosen A: The fox met an owl.

prompt B: What is 1+1?
rejected B: 2.
```

这两个不能比较。

RM 数据必须是：

```text
同一个 prompt
两个不同 response
一个 chosen
一个 rejected
```

例如：

```text
prompt:
What is 1+1?

chosen:
1+1 equals 2.

rejected:
1+1 equals 5.
```

这样才能训练：

```text
r(prompt, chosen) > r(prompt, rejected)
```

---

# 4. chosen\_input\_ids 和 rejected\_input\_ids 怎么构造？

通常会把 prompt 和 response 拼起来：

```text
<bos> prompt <sep> response <eos>
```

所以 chosen 样本是：

```text
<bos> Tell me a story. <sep> The fox met an owl. <eos>
```

rejected 样本是：

```text
<bos> Tell me a story. <sep> fox owl story bad. <eos>
```

然后分别 tokenizer 编码：

```python
chosen_input_ids = tokenizer.encode(
    "<bos> Tell me a story. <sep> The fox met an owl. <eos>"
)

rejected_input_ids = tokenizer.encode(
    "<bos> Tell me a story. <sep> fox owl story bad. <eos>"
)
```

于是 batch 里会有：

```python
chosen_ids   = batch["chosen_input_ids"]    # (B, T)
rejected_ids = batch["rejected_input_ids"]  # (B, T)
```

这里：

```text
B = batch size
T = 序列长度
```

---

# 5. 一个具体 token 例子

假设：

```text
<bos> = 2
<sep> = 4
<eos> = 3
```

prompt：

```text
Tell me a story.
```

编码为：

```text
[10, 11, 12, 13]
```

chosen response：

```text
The fox met an owl.
```

编码为：

```text
[20, 21, 22, 23, 24]
```

rejected response：

```text
fox owl bad.
```

编码为：

```text
[21, 24, 30]
```

那么：

```python
chosen_input_ids = [
    2, 10, 11, 12, 13, 4, 20, 21, 22, 23, 24, 3
]
```

对应：

```text
<bos> Tell me a story. <sep> The fox met an owl. <eos>
```

rejected：

```python
rejected_input_ids = [
    2, 10, 11, 12, 13, 4, 21, 24, 30, 3
]
```

对应：

```text
<bos> Tell me a story. <sep> fox owl bad. <eos>
```

注意：

```text
前面的 prompt 部分一样；
后面的 response 部分不一样。
```

RM 要学的是：

```text
chosen 这整段的分数 > rejected 这整段的分数
```

---

# 6. RM 训练时有没有 labels？

有，但不是 SFT 那种 token labels。

SFT 的 labels 是：

```text
每个位置的正确下一个 token
```

例如：

```text
Tell -> me
me -> a
a -> story
```

RM 的 label 是偏好关系：

```text
chosen 比 rejected 好
```

可以理解成：

```text
pair label = 1
```

意思是：

```text
第一个回答 chosen 应该胜过第二个回答 rejected。
```

但代码里不一定显式写 `label=1`，因为数据顺序已经规定了：

```text
chosen 在前
rejected 在后
```

所以损失函数默认希望：

```text
r_chosen - r_rejected > 0
```

---

# 7. Reward Model 的输出是什么？

你的代码：

```python
_, _, _, r_chosen   = model(chosen_ids,   targets=None)
_, _, _, r_rejected = model(rejected_ids, targets=None)
```

说明模型最后返回了 reward：

```text
r_chosen
r_rejected
```

一般形状是：

```text
r_chosen.shape = [B]
r_rejected.shape = [B]
```

或者：

```text
[B, 1]
```

它们都是标量分数。

比如 batch size = 4：

```text
r_chosen   = [2.1, 0.8, 1.5, -0.2]
r_rejected = [0.3, 1.1, 0.2, -1.0]
```

每一对都比较：

```text
样本 1：2.1 > 0.3，对
样本 2：0.8 < 1.1，错
样本 3：1.5 > 0.2，对
样本 4：-0.2 > -1.0，对
```

---

# 8. RM 怎么从一整段文本得到一个分数？

一般有两种常见做法。

## 做法一：取最后一个 token 的 hidden state

输入：

```text
<bos> prompt <sep> response <eos>
```

经过 GPT 后，每个位置都有 hidden state：

```text
h_0, h_1, h_2, ..., h_last
```

然后取最后一个有效 token 的 hidden state：

```text
h_last
```

通过一个 reward head：

```text
reward = Linear(h_last) -> scalar
```

也就是：

```text
r = w^T h_last + b
```

这个分数表示：

```text
模型对整段 prompt + response 的质量评价。
```

## 做法二：对多个 token hidden state 池化

比如 mean pooling，但在 GPT reward model 里，常见还是取最后有效 token，尤其是 `<eos>` 位置。

你可以简单记：

```text
Reward Model = GPT backbone + 一个输出标量的 reward head
```

---

# 9. 为什么 `targets=None`？

因为 RM 不是做语言模型训练。

SFT / 预训练时：

```python
model(input_ids, targets=labels)
```

模型会算 next-token loss。

RM 训练时：

```python
model(input_ids, targets=None)
```

表示：

```text
不要算 token cross entropy；
只需要前向得到 reward score。
```

然后外部用 Bradley-Terry loss 比较两个 reward。

所以：

```text
SFT loss：预测下一个 token
RM loss：chosen 分数要大于 rejected 分数
```

---

# 10. Bradley-Terry 损失在干什么？

你的代码是：

```python
loss = -F.logsigmoid(r_chosen - r_rejected).mean()
```

先看：

```text
r_chosen - r_rejected
```

这个差值非常重要。

记作：

```text
d = r_chosen - r_rejected
```

如果：

```text
d > 0
```

说明 chosen 分数更高，模型判断正确。

如果：

```text
d = 0
```

说明模型觉得两个一样好。

如果：

```text
d < 0
```

说明模型认为 rejected 更好，模型判断错了。

---

# 11. 为什么用 sigmoid？

Bradley-Terry 模型把两个回答的分数差转成概率：

```text
P(chosen better) = σ(r_chosen - r_rejected)
```

也就是：

```text
P = 1 / (1 + exp(-(r_chosen - r_rejected)))
```

如果 `r_chosen - r_rejected` 很大：

```text
P 接近 1
```

表示模型很确信 chosen 更好。

如果差值是 0：

```text
P = 0.5
```

表示模型分不清。

如果差值是负数：

```text
P 小于 0.5
```

表示模型倾向 rejected，更糟糕。

---

# 12. 为什么要取负 log？

我们希望最大化：

```text
P(chosen better)
```

也就是让这个概率越接近 1 越好。

训练里通常是最小化 loss。

所以最大化概率等价于最小化负对数概率：

```text
loss = -log P(chosen better)
```

代入：

```text
P(chosen better) = σ(r_chosen - r_rejected)
```

得到：

```text
loss = -log σ(r_chosen - r_rejected)
```

这就是：

```python
-F.logsigmoid(r_chosen - r_rejected)
```

所以这行代码就是 Bradley-Terry loss：

```python
loss = -F.logsigmoid(r_chosen - r_rejected).mean()
```

---

# 13. 用数字彻底看懂 loss

## 情况一：RM 判断正确，而且很自信

```text
r_chosen = 5
r_rejected = 0
d = 5
```

```text
σ(5) ≈ 0.993
```

loss：

```text
-log(0.993) ≈ 0.007
```

很小。

说明模型已经做得很好。

---

## 情况二：RM 分不清

```text
r_chosen = 1
r_rejected = 1
d = 0
```

```text
σ(0) = 0.5
```

loss：

```text
-log(0.5) = 0.693
```

说明模型相当于瞎猜。

---

## 情况三：RM 判断反了

```text
r_chosen = 0
r_rejected = 5
d = -5
```

```text
σ(-5) ≈ 0.0067
```

loss：

```text
-log(0.0067) ≈ 5.0
```

loss 很大。

说明模型严重错了。

---

# 14. 这行 loss 会怎样推动模型更新？

```python
loss = -F.logsigmoid(r_chosen - r_rejected).mean()
```

它只关心：

```text
r_chosen - r_rejected
```

训练目标是让这个差值变大。

也就是说，它会推动模型：

```text
提高 r_chosen
降低 r_rejected
```

更准确地说：

```text
chosen 分数应该比 rejected 分数高，而且高得越明显越好。
```

但是注意：

```text
RM 学到的是相对偏好，不是绝对分数。
```

例如：

```text
r_chosen = 5, r_rejected = 1
```

和：

```text
r_chosen = 100, r_rejected = 96
```

差值都等于 4。

Bradley-Terry loss 只关心差值，不关心绝对值。

---

# 15. 为什么不是用 MSE？

你可能会问：

```text
为什么不直接让 chosen = 1，rejected = 0，用 MSE？
```

比如：

```text
loss = (r_chosen - 1)^2 + (r_rejected - 0)^2
```

不是不行，但不太适合偏好建模。

因为人类偏好数据通常只告诉你：

```text
A 比 B 好
```

并没有告诉你：

```text
A 的绝对分数是 1.0
B 的绝对分数是 0.0
```

Bradley-Terry 更符合这种数据形式：

```text
只学习相对排序，不强行规定绝对分数。
```

这正是 RM 的核心。

# 16. 训练循环逐行解释

你的训练代码：

```python
while iter_num < config.rm_max_iters:
    chosen_ids   = batch['chosen_input_ids']    # (B, T)
    rejected_ids = batch['rejected_input_ids']  # (B, T)
```

意思是从数据里取一个 batch。

每个 batch 里有 B 对偏好样本。

每一对都有：

```text
chosen_input_ids
rejected_input_ids
```

---

```python
if chosen_ids.size(1) > config.block_size:
    chosen_ids = chosen_ids[:, :config.block_size]
if rejected_ids.size(1) > config.block_size:
    rejected_ids = rejected_ids[:, :config.block_size]
```

这是截断。

因为 GPT 的最大上下文长度有限，比如：

```text
block_size = 128 / 512 / 1024
```

如果序列太长，就截断到最大长度。

不过要注意，实际严谨训练里，最好别粗暴把 response 关键部分截掉。更好的做法通常是保证：

```text
prompt + response + eos 不超过 block_size
```

或者设计合理截断策略。

---

```python
_, _, _, r_chosen = model(chosen_ids, targets=None)
```

这一步：

```text
把 prompt + chosen response 输入 RM，得到 chosen 的奖励分数。
```

---

```python
_, _, _, r_rejected = model(rejected_ids, targets=None)
```

这一步：

```text
把 prompt + rejected response 输入同一个 RM，得到 rejected 的奖励分数。
```

注意：这是同一个模型，同一套参数。

不是两个模型。

---

```python
loss = -F.logsigmoid(r_chosen - r_rejected).mean()
```

这一步：

```text
比较 chosen 和 rejected 的分数差；
希望 chosen 分数更高。
```

---

```python
optimizer.zero_grad()
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), config.grad_clip)
optimizer.step()
```

这就是标准训练：

```text
清空旧梯度
反向传播计算新梯度
梯度裁剪防止爆炸
optimizer 更新参数
```

# 17. 为什么说“两次前向，共享权重”？

因为你代码里调用了两次：

```python
model(chosen_ids, targets=None)
model(rejected_ids, targets=None)
```

所以计算上是两次前向。

但它们用的是同一个模型对象：

```text
model
```

所以参数共享。

这非常重要。

因为我们希望同一个 RM 同时给 chosen 和 rejected 打分。

如果 chosen 用一个模型，rejected 用另一个模型，那分数没有可比性。

所以正确理解是：

```text
同一个 Reward Model 分别看两个回答；
输出两个标量；
用这两个标量做比较损失。
```

---

# 18. 评估指标 pairwise accuracy 是什么？

代码：

```python
acc = (r_chosen > r_rejected).float().mean().item()
```

它的意思是：

```text
有多少比例的样本中，RM 给 chosen 的分数高于 rejected？
```

例如 batch size = 5：

```text
r_chosen   = [2.1, 0.8, 1.5, -0.2, 3.0]
r_rejected = [0.3, 1.1, 0.2, -1.0, 2.5]
```

逐个比较：

```text
2.1 > 0.3   True
0.8 > 1.1   False
1.5 > 0.2   True
-0.2 > -1.0 True
3.0 > 2.5   True
```

结果：

```text
[True, False, True, True, True]
```

转 float：

```text
[1, 0, 1, 1, 1]
```

平均：

```text
4 / 5 = 0.8
```

所以：

```text
acc = 80%
```

意思是 80% 的偏好对排序正确。

---

# 19. acc = 0.5 为什么表示在猜？

因为每个样本只有两个选项：

```text
chosen
rejected
```

如果模型完全随机，它猜 chosen 比 rejected 高的概率大约是：

```text
50%
```

所以：

```text
acc = 0.5
```

说明模型基本没学到偏好。

如果：

```text
acc = 0.7+
```

说明模型已经能比较稳定地区分 chosen 和 rejected。

你项目里：

```text
PyTorch: 73.03%
TensorFlow: 76.80%
```

这说明 RM 已经学到了一定偏好信号。

---

# 20. loss 和 acc 的区别

loss 看的是：

```text
分数差的置信程度
```

accuracy 看的是：

```text
排序方向对不对
```

比如：

```text
r_chosen = 0.01
r_rejected = 0.00
```

accuracy 是对的，因为：

```text
0.01 > 0.00
```

但是 loss 不会特别低，因为模型只是略微认为 chosen 更好，不够自信。

再比如：

```text
r_chosen = 10
r_rejected = 0
```

accuracy 也是对的，loss 会非常低。

所以：

```text
accuracy 只看有没有排对；
loss 还看排对的 margin 够不够大。
```

这里的 margin 就是：

```text
r_chosen - r_rejected
```

假设数据：

```python
{
    "prompt": "What is 1+1?",
    "chosen": "1+1 equals 2.",
    "rejected": "1+1 equals 5."
}
```

构造输入：

```text
chosen_text:

rejected_text:

```

tokenize：

```python
chosen_input_ids = [...]
rejected_input_ids = [...]
```

前向：

```python
r_chosen = model(chosen_input_ids)
r_rejected = model(rejected_input_ids)
```

假设输出：

```text
r_chosen = 1.8
r_rejected = -0.5
```

```text

```

loss：


说明这条样本学得不错。

如果模型输出反了：

```text
r_chosen = -0.5
r_rejected = 1.8
```

差值：

```text
d = -2.3
```

概率：

```text
sigmoid(-2.3) ≈ 0.091
```

loss：

```text
-log(0.091) ≈ 2.40
```

损失就很大。

# 22. RM 和 SFT 的损失函数对比


| 阶段     | 输入                     | 输出          | 损失函数                    | 学到什么         |
| -------- | ------------------------ | ------------- | --------------------------- | ---------------- |
| Pretrain | 连续文本                 | vocab logits  | next-token cross entropy    | 语言规律         |
| SFT      | prompt + response        | vocab logits  | response-only cross entropy | 按指令回答       |
| RM       | prompt + chosen/rejected | scalar reward | Bradley-Terry loss          | 判断哪个回答更好 |

你现在这一步是 RM，所以：

```text
不再用 prompt-masked token loss；
而是用 chosen/rejected 的 pairwise ranking loss。
```

# 23. 最容易混淆的三个点

## 第一，RM 不是生成模型训练

虽然 RM 底层可能还是 GPT backbone，但训练目标不是生成下一个 token。

它的目标是：

```text
给完整回答打一个标量分数。
```

---

## 第二，chosen/rejected 不是两个类别分类

不是让模型输出：

```text
chosen 类 / rejected 类
```

而是让模型分别对两段文本打分：

```text
r_chosen
r_rejected
```

然后比较分数差。

---

## 第三，reward 的绝对值不重要，差值重要

Bradley-Terry loss 只关心：

```text
r_chosen - r_rejected
```

所以：

```text
chosen = 3, rejected = 1
```

比：

```text
chosen = 100, rejected = 98
```

在这个 loss 里差不多，因为差值都是 2。

---

# 24. 你可以用“老师打分”理解 RM

SFT 是学生学写答案。

RM 是老师学打分。

数据告诉老师：

```text
这份答案比那份答案好。
```

老师不需要知道每份答案绝对多少分，只需要学会排序：

```text
好答案分数高
差答案分数低
```

训练完成后，RM 可以拿来给生成模型的回答打分。

比如 PPO 里：

```text
生成模型生成 response
Reward Model 给 response 打分
PPO 让生成模型更倾向于生成高分回答
```

# 25. 最后总结

Reward Model 的数据构造是：

```text
每条样本包含：
prompt
chosen response
rejected response
```

拼接方式是：

```text
chosen_input = <bos> prompt <sep> chosen <eos>
rejected_input = <bos> prompt <sep> rejected <eos>
```

Reward Model 的输出是：

```text
r_chosen = RM(chosen_input)
r_rejected = RM(rejected_input)
```

损失函数是：

```text
loss = -log sigmoid(r_chosen - r_rejected)
```

意思是：

```text
希望 chosen 的分数高于 rejected。
```

评估指标是：

```text
pairwise accuracy = 有多少比例满足 r_chosen > r_rejected
```

你最应该记住这一句：

```text
SFT 训练模型“根据 prompt 生成 response”；
```
